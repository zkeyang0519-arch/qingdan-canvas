# Pi 任务 Harness

主聊天已接入本机 Pi 任务 harness。Pi 可以记录目标和信息缺口，查询当前项目资料，加载已授权工具，保存必要问题，并在结束前检查交付证据。任务、聊天轮次和外部平台任务分别保存状态。

2026-11-27 更新：交办任务先生成带子任务标题的计划卡，用户点击“确认并开始执行”后推进。当前操作写在对应任务名下，运行行柔和明暗变化；完成后的卡片与最终总结共同保留在聊天记录中。等待、中断及失败也保留实际状态。正常正文不被固定等待提示替换；缺少有效正文时，根据实际成果、未完成步骤和问题生成收尾说明。

同日 v3 更新：先修执行前检查、依赖阻塞、结果来源与错误归因，再减少主模型调用和重复上下文。主聊天与独立入口启用 v3；旧适配器仍可显式使用原协议。累计模型请求和 token 预算继续为 `null`（不限），任务卡、确认一次后连续执行、完成后保留卡片的交互保持不变。

运行链路是：用户交办 → 模型提出具名步骤、依赖和验收要求 → 宿主检查实时能力与已知参数 → 用户确认计划 → 宿主执行参数已明确的步骤，遇到需要判断的内容再交给模型 → 原任务状态查询 → 宿主核验实际成果 → 交付总结。明确的阻塞进入等待或中断，不靠增加模型调用空转。

现在继续使用 `npm run dev` 的原主入口（8790/8788）。账号、会话、历史和模型选择继续由原 Worker 保存；该账号的请求交给本机 Pi 执行。独立的 `npm run dev:pi` 仍可用于隔离试用。本次已加载主聊天服务，没有发布桌面或线上版本。

## 主聊天接入

主服务启动时读取 `.tmp/pi-main/profile.json` 中的账号与项目映射，建立仅监听回环地址的执行端。Worker 与执行端使用启动时生成的内部凭据通信；该凭据放在当前 Windows 用户和 SYSTEM 可访问的状态目录中，不进入前端或模型上下文。

每轮沿用原聊天选中的模型 ID、服务地址、API 格式及密钥，支持 Responses 和 Chat Completions。改变账号默认模型不会替换已有聊天选择。密钥由 Worker 校验授权后交给本机进程，运行态模型密钥不写入 Pi 检查点。Pi 不可用时明确报告连接故障，不退回旧的无工具聊天。

在「设置 → 主模型 → 管理连接」可以编辑或删除自建模型连接。编辑预填服务商、API 地址、接口类型和模型 ID；密钥不回显，留空保留，填写则替换。改到另一域名时，须提供新密钥或明确选择沿用当前密钥。保存不会调用付费模型。保存失败保留表单，重复提交同一次修改复用已保存的配置。

编辑会把相关聊天及默认选择同步到新设置；已经启动的请求仍固定使用原配置。内部用新连接编号保存新版本并保留旧作业引用，避免把运行中的请求或旧密钥意外发往新地址。主入口原子更新关联聊天；独立试用入口在读取与发送时解析最新配置。删除前说明影响，正在执行该连接的任务需先结束或停止；删除会清理该连接各版本的已保存密钥，保留聊天与历史模型名称。删除当前或默认连接后明确要求重选，不静默切换到其他服务。环境提供的内置连接仍由本机配置管理。

模型设置验收（2026-11-27）：接口与交互定向回归 34 项通过，另有历史消息兼容回归 4 项通过；覆盖预填、失败重试、跨域密钥沿用选择、运行中的旧配置、默认与聊天选择迁移、并发修改、丢失回执后的幂等重试、凭据清理、账号隔离及删除后的明确重选。桌面和 390px 窄屏用实际组件验证了编辑与删除，未修改真实连接或调用收费模型。类型检查与部署前构建通过。最后全量 1,915 项中 1,914 项通过，唯一失败是隔离启动器未在 15 秒内就绪；该测试原样单独复测通过，未改动其断言或启动器实现。源码入口已在活动任务为零时更新，不代表桌面或线上发布。

现有 MCP 的服务器配置、连接来源和当前项目设置会一次性继承到主聊天运行目录。WAAO 的 OAuth 注册、PKCE 和令牌按账号及回调入口独立保存，不再复用 8797 试用入口的授权状态；官网授权还须经 WAAO `account_get` 核验。WAAO 只保留当前项目的服务开关：旧项目选过工具则迁移为开启，空选择保持关闭；其他 MCP 的逐工具选择不变。开启后自动发现 WAAO 工具目录，项目、组织、预算和操作权限仍由 WAAO 判断。小目录直接提供工具；大目录最多预加载 6 项，其他能力通过发现和加载工具按需使用。

每次工具操作前重新检查原聊天的账号登录、项目绑定、摘要版本及记忆版本。摘要或记忆版本变化时不把旧检查点重新交给模型。工具面板、连接问题、任务停止、图片和视频回执均使用原账号权限。待办与记忆候选仍由用户审核保存。主聊天 Pi 的活动任务计入服务停止检查；服务中断保存为可恢复检查点，只有用户明确取消才标记取消。

## 使用

直接在原聊天输入任务即可，例如：“根据项目资料整理活动日期、地点和报名截止；缺少的信息先查资料，仍无法确定时问我。”普通问答直接回答；交办任务先由模型拆分有名称的子任务，宿主保存目标、要求和步骤，生成待确认卡片。待办清单还提供“交给轻单规划”：把所选项目的待办及执行要求、完成标准放进一段新聊天，保留原聊天草稿；原 Codex 执行入口继续单独提供。

任务进展在聊天内按小任务列出。模型可为步骤提供 `title`；没有标题时使用步骤描述或业务操作的中文名称。文本增量只处理公开回复，不显示推理内容。必要问题可以选择建议答案或自由输入，点击“回答并继续”后发送；选择选项本身不提交。问题和回答草稿都保留，回答携带原任务与问题编号，过期问题不能恢复另一个任务。

回答输入和发送分别控制：运行中的任务问题通过独立回答队列提交，不必等待整轮聊天收尾；空闲时仍沿用原聊天发送流程。已收到的回答显示回执并防止重复提交，宿主在下一次安全边界读取回答。队列按账号、项目、聊天、任务和问题隔离，重启后可恢复；过期计划确认、记忆版本变化、明确停止不会被旧回答绕过。回答事件不伪造云端消息编号。消息投递本身尚待核对时仍保留草稿并说明原因。

主入口与独立试用入口启用 `requirePlanConfirmation`。确认前允许查阅上下文、发现和加载能力，业务工具调用在宿主入口被拦截。计划确认绑定任务、计划内容和当前问题编号，普通“继续”或模型文字不能替代确认。计划目标、交付要求或步骤变更会使旧确认失效；单纯状态与执行回执更新不会重新确认。用户也可以在卡片里“调整计划”。旧协议测试适配器可以显式保持原执行模式。

步骤用 `requirementIds` 关联验收项，用 `dependsOn` 声明前置步骤，独立步骤显式填空数组。参数已明确时可以声明 `execution: {tool, args}`：`{$step: "draft", path: ["text"]}` 精确引用前一步稿件，`{$step: "node", path: ["created", 0, "node_id"]}` 引用真实对象编号；已采用的原文也可通过 `$artifact` 引用。引用只允许已声明的前置步骤和当前任务产物，不执行任意代码。宿主负责已确定步骤的执行和打勾；模型声明 `done` 不能替代真实证据。

需要模型判断时，模型用 `activeStepId` 关联当前子任务。MCP progress 通知、Codex 命令/文件/MCP 操作通知进入对应的操作行；不把推理文字当命令，不打印凭据。提问可指定 `blocksStepIds` 和 `checkedSources`；宿主检查可见资料编号并阻塞依赖链，其他独立步骤仍可继续。用户补充新要求时，旧的声明式步骤不会先于模型核对新要求自动执行。

模型准备结束而任务尚未验收时，宿主向 Pi 提供缺口并请求继续。连续三次结束检查中没有新的状态或证据时，保存检查点并停止空转。可以补充信息后继续。用户在新的消息中修改目标时，模型可显式修订目标与验收条件，原目标保留在记录里。

输入框中的停止按钮可以停止当前任务，包括待确认计划、本机自动续跑和后续轮询。已经被外部平台受理的任务保留原回执，不声称已取消平台工作。

## 信息与上下文

- `update_task` 维护目标、要求、步骤和信息缺口。已有要求不能在同一条请求执行途中被削减。
- `search_context` 和 `read_context` 搜索、分段读取本轮获准可见的对话、记忆、项目摘要、稿件和工具回执。
- `ask_user` 创建持久化问题。通过卡片回答时校验问题身份；直接在聊天补充时关联当前唯一待回答问题。
- 任务检查点保存工具消息与结果配对；采用稿、产物来源与内容指纹独立保存。恢复时优先提供原目标、最近补充和当前产物，再按模型输入预算保留完整工具请求与返回。大段历史、完整产物和早期证据可按编号读取，不再因某个用户轮次过大而把该轮所有成果从恢复上下文丢掉。
- v3 每轮请求重新读取宿主状态，主要提供当前步骤、相关要求、产物引用与最近证据。`task_plan` 可读取完整计划，`history_*` 可按当前任务读取完整归档，`read_context adopt:true` 可保存精确原文。重复的计划更新、能力加载结果压缩为状态；完整回执和原文仍在任务库中。规划和执行的工作上下文软目标分别为约 20,000 / 12,000 个估算 token；关键输入与最近完整工具对可扩展到模型真实容量，不属于累计预算限制。
- 上下文容量采用保守 token 估算，预留输出与工具定义；关键输入本身超出容量时明确报错并保留成果，不静默删除原目标。任务累计额度与单次模型上下文容量分别管理。
- 任务作用域包括账号、绑定和聊天。模型上下文与任务卡片不暴露宿主凭据；被遗忘的消息及不同记忆版本不能恢复到旧任务上下文。

原始聊天轮次仍通过 Pi RPC 运行。任务检查点、回执索引和事件由宿主 SQLite 保存，不依赖 Pi 子进程一直存活。

## 能力发现与扩展

`find_capabilities` 从实际目录返回能力与连接状态，并自动加载最多 4 项相关的已授权工具；`loaded:true` 可直接调用，省去单独加载的一轮模型请求。当前步骤的已知工具也由宿主准备。活动工具定义最多 8 项，同时受定义 token 预算约束；已加载定义复用，但执行仍检查最新授权。未加载的已知工具仍可用 `request_capability` 请求；连接不可用时可以触发原有的只读检测与维护流程。

计划确认前核对接口是否存在、服务是否开启、授权状态、依赖与声明参数。缺接口不能解释成登录失败，更不能无提示地换成宏执行；替代路径必须写进计划再确认。权限与预算仍由 WAAO 服务端决定。宏修改后进入待确认版本时，依赖它的步骤阻塞，只查询同一个宏，等待官网启用相应版本。

工具与项目资料搜索支持中文分词、英文标识符拆分、名称优先和关键词相关性排序。长查询不再依赖整句字符串包含。返回当前匹配项与目录总数；零匹配不能被解释成账号没有资源。

WAAO 项目服务关闭返回 `service_disabled`，与官网授权失效区分；其他 MCP 未选择的工具仍返回授权缺口。用户在工具设置连接或启用后，后续运行可发现并使用。WAAO 服务开关、身份、来源或工具定义在执行期间改变时，每次调用仍检查最新状态，关闭再开启也不会恢复旧调用句柄。官网拒绝具体操作时保留原因、所需权限和处理入口，不把单项拒绝误报成整个连接失效。

`create_capability` 可以将已授权的基础工具组合为新的 `qd_recipe_*` 工具。输入只接受字符串、数字和布尔值；参数可引用命名输入或前面步骤的结果。宿主拒绝未知工具、递归组合、前向引用、危险属性和过深嵌套。

组合通过结构校验后注册，实际执行时逐步检查权限和结果。结构校验不代表外部工具执行成功。每个有副作用的步骤保存回执，恢复组合时复用已完成步骤；投递不明的步骤先核对，不自动重发。

当前新增能力范围是现成 MCP 的按需加载和受限声明式组合。任意代码工具的生成、沙箱验证和包安装尚未接入；模型找不到现成能力时需要说明缺失服务及连接方式。

## 完成判定与外部等待

`submit_result` 对每项要求提交证据。宿主检查要求是否有对应项、引用是否存在且成功、是否仍有阻塞信息、未回答问题或未完成步骤。

验收类型：

| 类型          | 检查                                                     |
| ------------- | -------------------------------------------------------- |
| `answer`      | 保存实际正文；多项文字要求逐项对应，文本质量仍由模型核对 |
| `tool_result` | 必须引用宿主保存的成功工具回执                           |
| `media_ready` | 必须有平台返回成片引用的就绪回执                         |

这些检查防止缺失产物、失败回执和未完成步骤被直接当作成功，不保证语义质量。当前媒体检查依据平台返回的媒体地址，尚未加入播放器测试、时长画幅检测和视觉质检。模型仍需把验收范围与用户要求对应起来，不能用平台就绪回执代替用户要求的其他验证。

验收项可通过 `tool` / `tools`、`operation`、`resource` 和 `inputArtifactId` 约束实际成果。宿主从工具名称、输入与原始回执确定操作、目标对象、采用稿指纹和结果状态；模型不能自行声明这些事实。新建节点要求真实创建回执，读取旧画布或积分查询不能替代。媒体结果必须沿同一服务、同一生成任务绑定到本次提交；每次查询直接关联最初提交，长时间轮询不会丢失来源。宏运行成功仅证明工作流结果，不能证明图片就绪；采用替代路径时，仍需本次节点与实际生成快照对应。未知工具的业务语义仍需要明确工具约束或专用适配。

WAAO 返回可识别的原任务编号后，宿主自动保存等待。专用 `waao`、`node_generate` → `task_get`、宏启用状态与 `macro_run` → `macro_run_get` 可自动查询；其他支持的回执仍可通过 `wait_for_result` 登记。宿主每 15 秒查询原回执，等待期间不调用主模型；结果满足全部验收项时直接交付，仍需判断的后续工作才唤醒 Pi。平台拒绝状态查询时停止轮询并保存具体原因。服务重启后恢复等待，查询前核对项目、聊天可见性与当前工具授权。

单次外部等待最多 30 分钟、120 次查询。其他工具可以保存等待检查点，但尚未接入各自的自动轮询适配，需要后续继续查询。重复轮询不会再次调用生成提交。

## 预算与恢复

默认不限制任务累计请求、token 或单段请求次数，`null` 表示不限额度；仍记录实际用量，并通过无进展检测、请求超时与持久化检查点管理运行。取消累计额度不取消模型自身上下文容量。调用方仍可显式配置测试或业务预算，预算跨进程恢复累计。

显式预算耗尽或请求中断时保存检查点。用户发送“继续”可恢复。授权和付费生成参数继续由原工具执行层控制，不因不限累计额度而扩大权限。

有副作用的调用区分已发送、明确未发送、收到回执和投递未知。收到回执后复用结果；明确未发送的 MCP 调用可以重试；投递未知的操作不能自动重发。状态查询属于只读操作，不复用过期进度。

明确没有受理工作的权限拒绝，可在用户处理后发起新一轮重试；同一轮不能反复重发。待批准操作、成功回执与投递未知均不使用这项例外。402 余额不足、401/403 鉴权、429 限流、上下文溢出、模型网络错误和本地中断分别记录；工具错误不归类为模型故障。不可重试的模型拒绝直接结束本轮并保留成果。任务卡折叠展示请求数、工具回执和累计 token（含重复上下文及缓存），继续标明累计预算不限。

同一聊天通过持久化租约限制为一个有效任务执行者。用户取消、旧进程写入和异步结果回写都受到当前状态和租约约束。
