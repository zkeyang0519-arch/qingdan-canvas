设置保留三个入口；每个 Agent 的专属选项收进自己的详情。

所有工具共用列表，模型、速度等选项只在支持它们的服务里出现。

列表支持搜索与 Agent / MCP 筛选。接入、断开、检测、认证、工具选择和诊断进入详情；设置中的模型连接与工具连接使用不同名称。未来新增 Agent 需新增对应适配器，并声明其能力，不能只加一个名字就声称可用。

现有执行默认值硬编码 Codex，需要迁移成按服务实例保存。

编程任务可指定默认 Agent，图片等任务仍由 Pi 调用相应 MCP 工具。

“默认 Agent”只用于需要 coding agent 的任务，不把所有 MCP 调用转交 Codex。待办提交前可改本批次执行者；无法满足能力或权限时展示缺失项，不默默换成另一付费服务或扩大权限。设置变化只影响后续任务，已有批次保留快照。

待办继续原行编辑，权限继续使用紧凑入口，并明确适用范围。

沿用已有四档权限及用户选择；不同 Agent 只展示能准确映射的档位。文件权限不代表 WAAO 等服务的写入或付费授权，远端授权仍由服务详情与实际调用共同约束。“已连接”和“当前项目可调用”分别展示。

项目资料先回答“现在到哪了”，交接报告和读取日志放到第二层。

概览、交接报告和证据共用一份数据，按阅读深度展开。

位置呈现内容
概览首屏一句目标、当前进展、下一步、阻碍或待核实；没有内容的区块不占位。模块进度按行展示，点击再看当前 / 剩余 / 下一步。
交接报告完整背景、近期改动、修改入口、验收和交接细节。保留原内容，通过“更多”打开，不与概览叠放。
来源与版本更新时间、来源类型、读取范围、覆盖缺口、旧摘要；会话 ID、Git 基线、运行编号收进技术详情。第一阶段只展示已有旧版，完整版本库另需存储。
生成记录读取步骤、实时输出、停止、异常恢复。默认折叠，异常自动展示相关操作；正常状态不常驻“刷新总结状态”。

已有结构化摘要字段可以复用，第一步无需重写总结服务。

更新期间保留上次结果，失败或来源过期时说明当前看到哪一版。

显示更新时间与“来源与版本”；聊天只显示一条摘要更新卡片。

显示阶段和“停止”。没有实际进度时不显示百分比。

给出失败原因、重试与旧版时间；没有旧版时保留空态，不伪造成功。

标为“需更新”，保留来源时间；不让历史“工具未连接”替代本轮连接检测。

 用户点击“更新摘要”才启动整理。默认基于聊天和任务记录；需要额外读文件时明确展示读取范围与执行服务。摘要缺失不应阻断普通聊天；确实依赖缺失项目事实时，harness 检索、核验或请求补充。生成完成仅代表摘要可读，不等同于项目测试通过。

任务结束后提炼可复用经验，个人偏好、项目约定与操作方法各归其位。

会重复使用的偏好保留；进度、待办、工具状态与权限各有单一归属。

信息放在哪里例子
个人偏好设置 → 个人偏好中文回答；先给结果；交付附运行方式。跨项目可用。
项目约定项目资料 → 约定与经验固定术语、品牌风格、技术选型和确认过的长期决策。限当前项目。
变化中的事实项目概览 / 待办 / 执行记录做到哪一步、失败原因、尚未验证的链路。不再复制一份到记忆。
连接与授权工具与 Agent / 本次执行登录、在线状态、工具勾选、读写权限。记忆不保存密钥，也不能授予权限。
旧 personal / project 记录保留原 ID、版本、来源和删除语义，直接换入口；不批量删除或让模型擅自重分类。任务结束后的明确长期偏好与已验证方法按下述规则自动整理；推测或冲突内容只生成建议，随时可以编辑或撤销。

现有记忆确实进入模型上下文；它不是没有作用的界面。

Pi 每轮同时看相关约定和当前工具能力，旧摘要不能决定今天能做什么。

现状已把记忆和摘要当作背景数据。后续加入相关性筛选与“本轮参考了什么”，避免无关记忆塞满提示词；新指示与旧偏好冲突时使用当前指示。被编辑或删除的记录继续走现有 revision / memoryEpoch 失效机制，不能从旧聊天重新复活。

每个已结束的任务触发一次轻量复盘，有值得复用的内容才沉淀。

这一步加入 harness 的任务收尾，不依赖某个 coding agent。主任务先交付；沉淀检查在后台运行，失败不改变任务完成状态。使用现有主模型做一次有预算、超时和输出上限的精简调用，默认最多 3 条；证据无变化时直接跳过。复盘读取已授权的任务材料，不重跑命令或再次调用付费生成工具。

每条候选说明适用条件和依据，并决定新增、合并、建议或舍弃。

内容保存位置与标准
明确的长期偏好用户明确说“以后都这样”或“记住”且范围清楚，可自动保存。只有明确跨项目适用时进入个人偏好；项目内要求进入项目约定。
已验证的操作方法先保存为本项目操作经验：何时适用、简短步骤、结果验证、来源与环境。成功必须有实际回执或验收依据，不能只凭模型自评。它是参考方法，不自动变成可执行工具。
推测出的习惯留下可编辑建议，不立即影响后续任务。例如“可能偏好先看交互方案”；可保存、忽略或修改适用范围，不弹窗打断。
重复、冲突或过时重复项合并证据，不增一条同义记录；冲突先保留差异建议，不能静默改写原规则。被删除或忽略的旧证据不得重新生成同一条。
没有长期价值本次进度、一次性命令输出、临时路径、连接在线状态、密钥和授权不进入长期记忆。已验证的排障方法可以保存，某次失败本身不能被概括成长期事实。
原“项目约定”扩展为“约定与经验”，仍是项目资料下的同一个二级入口；其中区分约定和方法。方法经后续任务重复验证后，可再提炼为技能或工作流草案，启用与执行沿用工具授权机制。无需为了沉淀再加一个顶层记忆模块。

任务结论和复盘任务分开存储，断线或重复回执不会重复写记忆。

监听任务最终结论及交付记录，而不是任意工具返回或聊天轮次结束。验收完成的任务进入复盘；明确终止的失败任务只能提炼有证据的局部经验。等待输入、等待外部结果或暂时中断不算结束。用户点击停止时不再启动新的模型调用，可保留已有复盘草稿。 新增独立复盘队列与候选表；方法类型与证据字段需扩展现有存储，不能假装现有 key/value 记忆已具备。宿主校验引用、权限范围、来源删除状态、expectedRevision 和 memoryEpoch 后写入。若用户已开始下一任务，自动记忆写入延后到空闲边界，避免现有 epoch 机制使正在进行的对话失效。

设置里可以选自动整理、仅生成建议或关闭，正常完成时无需逐次确认。

验收：同一结束事件只复盘一次；0 条候选安静结束；弱证据不激活；重复合并；冲突不覆盖；撤销后旧任务不复活记忆；并行任务与账户隔离；复盘超时不影响原结果；关闭后不再产生新调用。

Codex 适配内置进轻单；用户通常只管理一个“本机服务”入口。

独立连接器应用可以合并；本机进程管理与协议转换仍须有承担者。

使用场景建议接法用户看到什么
轻单桌面端内置本地服务启动并管理 Agent 适配器。Codex 已连接 / 需登录；无需再开一个连接器面板。
浏览器控制本机项目一套本机服务承接目录、进程、登录和执行回执。纯网页不能直接启动本机 CLI。连接这台电脑一次，多个本机 Agent 共用设备入口。
远程 Agent / MCP轻单后端连接已部署并授权的远端服务。添加服务和认证；不用为每个云端工具装本机程序。
这里“一个入口”不要求所有隔离会话共用一个进程。登录、子进程恢复、权限映射、会话续接、流式输出与执行回执仍由内部适配层维护。它是轻单的功能模块，不需要成为用户日常操作的另一套应用。

Codex 优先沿用 App Server，其他 Agent 接各自支持的协议。

App Server提供会话、授权和事件接口，适合轻单的交互式编程场景。现有客户端可复用。官方文档

依据当前代码和上述官方接口，我建议保留已有 stdio 路线，把 Pi、Runner 和独立诊断工具逐步统一到共享适配器。统一的是服务身份、配置与状态；第一阶段仍调用原执行路径，避免为了页面整洁一次性重写运行链路。MCP 是可用协议之一，不能假设每个 coding agent 都原生支持它。

步骤改动验收
1 · 收拢页面设置新增统一服务页；Codex 设置移到详情。项目摘要变成项目资料，记忆分别迁入口。保留上轮模型双行、权限入口和原行待办编辑。原有模型选择、独立默认值、自定义 / DeepSeek 模板、MCP 认证与工具勾选、模型刷新 / 快速模式 / 重置 / 保存、摘要停止 / 恢复 / 来源、记忆增删改均可从新入口完成。无迁移数据丢失。
2 · 解耦服务接入注册表和能力定义；旧 Codex 默认值迁到 Codex 实例下。账户配置、项目启用、单次任务覆盖分开；提交时记录最终执行者和配置。增加第二个模拟 Agent 不需给主设置加新 Tab；不支持的选项不出现；多个同名服务和不同账号不误合并。失败重试继续原任务。
3 · 精简上下文摘要移除聊天硬前置，保留时间与证据；相关约定按需带入；执行回执驱动摘要待更新状态；逐步共享本地适配器；加入任务后轻量复盘。复盘去重、撤销与并发写入正确；无摘要能普通聊天；旧“未连接”记录不能覆盖真实能力；记忆更新 / 删除失效正确；任一 Agent 掉线只影响其依赖任务。
