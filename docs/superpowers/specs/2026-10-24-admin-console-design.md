# 轻单管理员后台与账号管理

## 意图

为现有 `qingdan-canvas` 增加一个独立的 `/admin` 后台。用户名为 `moon` 的账号是初始管理员；管理员可以查看注册账号，修改账号资料，代为设置新密码，停用或恢复账号，并把其他账号提升为管理员或降为普通用户。普通用户继续只能管理自己的资料和密码。

当前密码实现已经满足加盐要求：`worker/passwords.js` 为每次密码生成独立的 16 字节随机盐，使用 scrypt（`N=16384`、`r=8`、`p=5`）派生 32 字节密钥，按 `scrypt$参数$盐$哈希` 格式保存。后台重置密码继续复用 `hashPassword`，不保存或返回明文密码，不新增另一套盐算法。

## 目标

- 在 D1 中持久化账号角色和停用状态，并让 `moon` 成为初始管理员。
- 只有当前有效管理员会话可以读取或修改管理员接口；前端隐藏按钮不能代替服务端权限检查。
- 后台显示账号 ID、用户名、昵称、已验证邮箱、注册时间、角色和停用状态。
- 管理员可修改昵称和邮箱；用户名保持不变，避免破坏账号引用和画布作者记录。
- 管理员可为目标账号设置符合现有规则的新密码；目标账号的已有会话全部失效。
- 管理员可提升/降级其他账号的管理员角色，停用/恢复其他账号。
- 停用账号不能登录、读取画布或继续使用已有 WebSocket；恢复后需要重新登录。
- 保留已有账号、画布、成员、头像和邮箱找回数据，不读出或迁移任何明文密码。

## 非目标与安全边界

- 后台不显示原密码，也不提供从哈希反推出密码的功能。
- 不直接删除账号；停用保留其画布、成员关系和作者记录。
- 不允许修改用户名；昵称和邮箱是本轮的账号资料字段。
- 不把管理员变成可以读取其他账号画布正文的超级数据浏览器；管理员操作仍只管理账号元数据。
- `moon` 作为受保护的主管理员：不能被其他管理员修改资料、重置密码、停用或降级；`moon` 自己仍可使用普通账号设置和邮箱找回流程管理自己的资料与密码。至少保留一个可恢复系统的管理员。其他管理员可以管理普通账号，并可管理除 `moon` 外的其他管理员。
- 本轮不做独立的管理员密码、批量导入、批量操作或完整审计报表；必要的管理员操作错误仍返回通用错误，不泄露密码哈希。

## 约束

- 项目使用 Cloudflare Workers、D1、R2、Durable Objects 和现有 React 前端，不增加认证依赖。
- 账号密码校验沿用当前 `accounts.ts` 的 9–128 字符规则和 `worker/passwords.js` 的 scrypt 编码格式。
- D1 迁移必须先于生产代码发布；本地测试使用独立数据库。
- 现有 `X-QD-Account` 身份绑定和同源校验继续生效；管理员接口不能接受 URL 或请求体中的任意用户身份作为授权依据。

## 方案比较与选择

1. **独立 `/admin` 页面（选定）**：增加管理员专用 React 页面和 `/api/admin/*` Worker 接口，共用当前登录会话，角色检查集中在服务端。与普通画布入口清晰分开，后续增加审计或批量功能有空间，改动也能局限在账号模块。
2. **首页内嵌抽屉**：实现更快，但后台操作与画布列表混在一个状态树中，移动端和后续扩展更容易拥挤。
3. **单独管理站点**：隔离最强，但需要额外部署、认证和资源配置，对当前单 Worker 项目成本过高。

选择方案 1，因为用户明确需要“进入管理系统”，且管理员角色会扩展到多个账号；独立入口能复用现有会话而不把后台逻辑散落在画布页面。

## 设计

### 数据与角色

新增 D1 迁移 `0006_admin_accounts.sql`：

- `accounts.role TEXT NOT NULL DEFAULT 'user' CHECK(role IN ('user','admin'))`。
- `accounts.disabled_at INTEGER`，`NULL` 表示可用，非空表示停用时间戳。
- 对已有数据执行 `UPDATE accounts SET role='admin' WHERE username='moon'`；如果迁移时 `moon` 尚未注册，部署说明提供一次性管理员初始化 SQL，不能因为用户名注册流程自动授予管理员。
- 增加用于后台排序的 `accounts_created` 索引（如实现需要）。

`Session`、`getSession`、`publicUser` 扩展 `role`；会话查询只接受 `disabled_at IS NULL` 的账号。停用或改密时删除目标账号的 `account_sessions`，使浏览器和 WebSocket 在下一次校验时失效。

### 服务端接口

新增 `worker/admin.ts`，由 `worker/index.ts` 在普通受保护路由之前分派 `/api/admin/*`。`requireAdmin(request, env)` 先调用 `requireSession`，再检查 `session.role === 'admin'`，所有目标账号 ID 都从路径解析并在 D1 查询。

- `GET /api/admin/accounts`：分页前的轻量列表，返回 `id`、`username`、`name`、`email`、`createdAt`、`role`、`disabledAt`；不返回 `password_hash`、会话令牌或恢复凭据。
- `PATCH /api/admin/accounts/:id`：修改昵称和邮箱。邮箱格式和长度沿用现有资料校验；管理员修改邮箱视为已验证的管理动作，保留现有找回流程的数据一致性。
- `POST /api/admin/accounts/:id/password`：接收新密码，复用现有长度校验与 `hashPassword`，更新哈希并删除目标账号全部会话；响应只返回目标账号的公开资料和“已要求重新登录”的结果。目标为 `moon` 时一律拒绝。
- `POST /api/admin/accounts/:id/role`：接收 `role: 'user' | 'admin'`。只允许作用于非 `moon` 账号；不能让系统没有管理员。
- `POST /api/admin/accounts/:id/status`：接收 `disabled: boolean`。只允许作用于非 `moon` 账号；停用时写入当前时间、删除所有会话，恢复时清空时间但不自动登录。

所有接口要求同源、有效 Cookie 和当前会话对应的 `X-QD-Account`；非管理员返回 403，未登录返回 401，目标不存在返回 404。并发更新使用带当前值/角色条件的 SQL 或重新读取后检查，避免旧页面覆盖新管理员操作。

### 前端入口与页面

- `App.jsx` 在 `location.pathname === '/admin'` 且已有会话时渲染 `AdminPage`；非管理员访问显示无权限提示并提供返回首页，不加载账号列表。
- 普通首页的账号菜单为管理员增加“管理后台”入口；普通账号不显示入口，但直接访问仍由服务端拒绝。
- `AdminPage.jsx` 使用现有 `api()`，显示响应式账号表格、搜索/筛选（用户名、角色、停用状态）和返回首页按钮。
- 每行提供“编辑资料”“设置新密码”“提升/降级管理员”“停用/恢复”操作；`moon` 行隐藏并由服务端拒绝所有管理员变更操作。危险操作需要二次确认，成功后刷新该行，不把密码写入 URL、localStorage 或日志。
- 目标是可操作的管理界面，不改变画布工作区和普通账号设置的既有交互。

### 密码加盐说明

不新增单独的 `salt` 列，也不在应用代码中加入固定“全局盐”。现有编码哈希已经包含每个账号独立的随机盐和 scrypt 参数。测试会验证：同一密码两次 `hashPassword` 的结果不同、`verifyPassword` 正确通过/拒绝、后台重置后数据库字段仍是编码哈希且目标旧会话被清除。

## 验证

- Worker 测试：角色迁移和 `moon` 初始化；非管理员访问所有 `/api/admin/*` 均被拒绝；管理员可以列表、编辑资料、改密、提权/降权、停用/恢复；`moon` 不能被降级或停用；最后一个管理员不能被移除；改密/停用会撤销目标会话；停用账号无法登录、快照或 WebSocket。
- 密码测试：随机盐、scrypt 参数、错误密码拒绝、重置不返回明文。
- 前端测试：管理员入口和 `/admin` 页面可见性、账号操作请求与确认、错误提示和非管理员拒绝态。
- 运行 `npm test`、`npm run check`、`npm run deploy:check`；不执行生产迁移或部署。

## 待实现者决定

- 表格分页和搜索只需支持当前账号规模；可以先一次加载列表，代码结构保留后续分页位置。
- 管理后台的视觉样式沿用现有 `auth.css`/首页卡片风格，不改变品牌色和画布布局。
- 对邮箱编辑使用现有 `email` 唯一约束，冲突时返回可理解的 409 错误。

## 设计审查结论

实现审查提出了主管理员保护、管理员自操作、并发保留管理员、首次初始化、邮箱挑战和 `/admin` 路由状态等问题。已作如下决定：

- `moon` 是受保护账号；其他管理员不能修改其资料或密码，也不能降级或停用；`moon` 自己沿用现有账号设置与邮箱找回。
- 管理员不能自我降级或停用；密码与资料修改通过现有账号设置完成，后台的角色/状态操作不允许作用于当前操作者。
- 提权、降权和停用使用带条件的原子更新并检查管理员数量，避免并发请求移除最后一个管理员。
- 迁移只提升已存在的 `moon`；若尚未注册，按部署说明在 `moon` 注册后执行一次性初始化 SQL，系统不会因为用户名相同而自动提权。
- 管理员修改邮箱时允许替换或清空，清除该账号未完成的邮箱挑战，并把新邮箱标记为管理员已验证；唯一约束冲突返回 409。
- 未登录访问 `/admin` 保留路径，登录后回到后台；非管理员显示无权限并回首页；当前后台账号失去权限后清空后台并回首页。
