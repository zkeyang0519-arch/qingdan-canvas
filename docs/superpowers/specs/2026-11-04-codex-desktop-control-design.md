# Codex 桌面与轻单双向控制

> 状态更新：用户后续明确改为“轻单统一控制执行，桌面只显示项目和会话”。下文双向控制方案保留为研究记录，不再作为实施范围；不再继续 SSH 配置。当前可见性与自动归组的实际验证边界见 [桌面显示记录](../../agent-desktop-visibility-verification-2026-11-04.md)。

用户于 2026-11-04 确认以下方案，并明确要求在 Codex 桌面直接补充、停止和继续任务。本文件记录已确认的范围；不是再次申请确认。

## 目标

轻单 MCP 派单后，Codex 桌面左侧出现对应本机项目和独立会话；两端操作同一条真实运行。执行中、等待输入/审批、停止中、已停止和本轮结束可核对；执行结束仍须验收，正式待办写回留在第 5 步。

## 已核实的起点

- 当前基线提交 `8808879`，分支 `feat/qingdan-mcp`，已有 583 项通过测试。
- Runner 自建 `codex app-server --stdio`，桌面历史可以读取其持久化会话；已有测试会话 projectId 为空。
- 当前 alpha.6 生成协议包含 project/list、project/create、thread/start.projectId、thread/metadata/update.projectId 和项目/会话/轮次通知。
- 当前默认共享控制 socket 不存在，`daemon version` 无法连接。已有桌面后台不可假设为可附加服务。

## 方案和边界

采用共享执行后台，保留轻单 MCP、设备鉴权、允许目录、持久化请求及恢复机制。只同步标题的方案不能满足直接控制；两边独立恢复同一线程可能产生冲突，因此不作为双向控制实现。

先实测受支持的共享连接及桌面接管，再实现产品路径。不修改 Codex 私有数据库、不拷贝凭据、不劫持桌面 stdio、不结束用户其他会话、不开放公网监听。共享后台由自己的生命周期管理；Runner 断开只能清理自己拥有的连接，不能杀掉共享服务器。

项目归属通过真实 API 建立，已授权规范化目录复用匹配项目，否则幂等创建。云端/model 不得指定任意本机 projectId、目录或权限。旧会话归组不能重发旧任务。

桌面在同一会话的补充、停止与续跑必须被识别为用户操作。新轮次不能被旧回执覆盖；不认识的身份、项目/权限变化或并发冲突进入待核对，不能重复派发。桌面发起的新要求不自动证明原待办通过验收。

版本管理检测实际连接的服务，保留已验证版本和协议能力记录；未知版本先诊断，只有受验证的组合可执行。不能承诺所有未来版本天然兼容，也不能把单纯绕过版本检查当作升级支持。

## 完成验收

轻单派单 → 桌面能查到正确项目下的同一会话 → 桌面补充/停止/继续 → 轻单收到真实状态及输出；全程同一 threadId，无重复执行。刷新、断开 Runner 后重新连接不丢记录，且不误杀共享后台。独立测试覆盖版本变更、丢事件、双端指令竞争和旧轮次迟到。新能力须在轻单提供可操作入口和明确诊断。
