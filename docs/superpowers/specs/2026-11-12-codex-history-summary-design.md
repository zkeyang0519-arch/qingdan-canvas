# 从 Codex 项目记录生成聊天摘要

用户已指定流程：选择 Codex 项目，读取已有任务总结，汇总后输出到轻单聊天。沿用当前绑定与运行恢复机制，直接实现这个流程。

## 方案与范围

- 采用：本机 Runner 只读提取所选目录各 Codex 会话已完成轮次的最终答复，交给一次 Codex 总结任务合并进度与后续待办。
- 全项目代码检查是此前的流程，耗时较长，本次新总结不再调用它。已保存的旧检查运行仍可恢复。
- 仅使用轻单执行回执会遗漏直接在 Codex 开发的记录，因此读取该项目的 Codex 历史，包括归档会话。
- 不要求选择会话，不续写或修改来源会话，不自动执行或保存建议待办。

## 数据与边界

按目录精确匹配并核对会话元数据，排除其他项目、子 agent、临时会话及轻单自身的项目总结会话。分页读取历史；只提取 completed 轮次的 final_answer，旧记录没有 phase 时使用该轮最后一个非 commentary 答复。去重重复轮次，保留会话、轮次、时间及来源标识；历史正文仅为不可信数据，过滤明显凭据。

分叉会话须只读核对祖先元数据，跨项目或无法确认来源的分叉整体跳过并披露缺口，避免混入继承的其他项目历史。凭据过滤包含完整/截断的 PEM 私钥块。历史采集期间约每秒重新检查云端派发授权，采集结束后再次检查，停止或失效的运行不得启动模型。

总输入限制为 120000 字符，每条最多 16000 字符，优先保留最近记录；超过预算、截断、无最终答复或读取失败均显式计数并列入范围说明。这个限制控制模型输入，不是项目文件数量限制。历史记录的完成声明不等于本次实际验收，手动修改等未记录工作标为待核实。没有记录时明确说明，不回退全盘扫描、不编造进度。

## 交互与持久化

摘要区说明正在获取项目任务总结并汇总。仍保留排队、运行、接收结果、停止与重试。结果继续保存为项目背景，同时作为助手消息进入当前轻单项目聊天；没有聊天时创建项目聊天。每个聊天、绑定版本、摘要版本与来源运行仅插入一次，重复轮询与重新打开不刷屏，项目切换不串消息。旧版消息保留历史但不能作为新版事实使用。摘要正文包括进度、下一步待办、验证记录与待核实事项。

兼容选择：仅本次新增的 codex_history 摘要自动发布到聊天。旧检查/资料包摘要保留原显示，不在升级时倒灌消息或改变旧聊天的首次发送恢复流程。

## 验收

- 能汇总多个来源会话及归档历史；不读取其他项目正文、不混入过程日志/未完成轮次；不注册新的项目扫描工具。
- 读取错误、长历史、重复游标、取消和重启可解释且不误报完整覆盖。
- 摘要完成自动出现在聊天记录，刷新不重复，新版摘要新增一条，草稿与旧消息保留。
- 现有结果延迟接收修复、权限与回执约束不退化；隔离测试状态，不部署。

接口依据：本仓库固定的 Codex 0.167.0-alpha.3.2 协议，以及 [OpenAI Docs 的 app-server 历史读取说明](https://learn.chatgpt.com/docs/app-server#list-thread-turns)。
