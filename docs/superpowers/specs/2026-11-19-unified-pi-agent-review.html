在原来的 Agent 聊天框里，Pi 通过星驰的 gpt-6.1-sol 回答，也能按需调用 Codex 和 WAAO。

原聊天框的每条新消息都进入本对话的 Pi 会话。

  • 用户操作　在原输入框按发送即可。已有的「短片制作」入口可带入选中的稿件、图片或待办，作为同一输入框的草稿。已有制作卡可展开查看资料。
  • 发送与显示　沿用登录、项目绑定、项目摘要的现有规则、输入法、草稿和发送回执。每次发送携带原 requestId，同一会话沿用已有单活跃回复约束。新状态以消息内的轻量进度行展示。
  • 验收　比较桌面 1440 像素和手机 390 像素的栏宽与页签。正文问答、回车发送、中文输入、关闭再打开和切换待办仍走原控件。

现有桌面和手机共用同一个项目聊天区。

Pi 同时注册两个工具，gpt-6.1-sol 可以直接回复，也可以连续调用工具。

切换前已实测 DeepSeek 普通问答、Codex 改稿和两张 1672 × 941 原图。原回复在桌面、手机宽度均可放大和切换，刷新后图 2 的文件摘要仍以 a833c51673dc 开头。旧回执 LOCAL-5CB56F8C 属于早期模拟试验。本地运行 Pi、轻单聊天和工具调度。主模型使用星驰的 Responses 接口，Codex 和 WAAO 分别使用各自在线服务。WAAO 官网已返回 OAuth 授权入口，登录后 Pi 读取可用的 MCP 工具、项目与视频服务。真实成片的验收依据是该账号的任务号与可播放原片。
  • 本机与后续云端　本机先用 workerd 运行聊天 Worker 和 Pi Agent Core 的 0.83.0 版本，及同版本 Pi AI。本机默认使用 gpt-6.1-sol，原有稿件、图号和工具回执按原会话读取。验收通过后，可将同一会话引擎和存储迁到云端 Worker，Codex 和 WAAO 的外部操作仍可交给绑定设备。
  • 工具选择　每轮都注册相同的两个工具。改词、生图、提交和查询是它们各自的动作。模型根据消息、当前稿件、可用素材、设备状态和刚返回的结果选择行动。工具名、参数和结果由 Pi 跟踪。轻单记录操作与权限。
  • 模型与配置　本机调用 https://api.xingchiapi.com/v1/responses。把星驰密钥填入项目根目录 .dev.vars.pi 的 XINGCHI_API_KEY，保存后刷新聊天页。密钥留空时可继续查看历史消息和图片。星驰账号的模型权限以首次带密钥的真实请求为准。服务状态同时报出模型和两项工具各自的可用性。模型调用保留工具消息的角色、调用编号及适配器所需的协议字段。
  • 普通对话　本机试用需要本机服务运行和星驰模型连接可用。迁云后，若项目摘要仍有效，Runner 离线时可由云端 Pi 回答普通问题。未绑定或摘要过期继续显示现有项目提示。设备工具离线时显示缺少的条件。

现有短片 Pi 会话按制作任务编号保存。新聊天会话改以聊天编号定位。

同一聊天跨设备重开仍能接话，切换项目会打开各自的记录。

  • 保存方式　复用账号对应的 Durable Object 和 chatId。把 Pi 的消息、工具调用和结果以有序事件保存，每个事件带会话与轮次。Pi 在下一次请求重建上下文，浏览器关闭也能回到同一段聊天。
  • 上下文预算　先保留用户本轮原文、项目摘要来源、已批准记忆、最近采用的稿版和图组，再选取近期文本。完整稿件和历史图组另存，可按权限和编号回读。对话很长时，仍能引用已选中的旧回复。
  • 已有功能　Pi 的最终文字继续映射到现有回复结构。待办候选和记忆候选由原按钮确认。流式文字和工具状态分别渲染。既有 Codex 项目执行、计划任务的专用执行权限继续有效。
  • 验收　在会话甲生成图，在会话乙直接说“第二张”应提示选择。用户从同一项目主动引用甲的一条消息后，乙才建立该图版的来源记录。

现有消息按 chatId 和 sequence 排序。

工具执行跨越请求时，Pi 能从原调用的结果继续。

  • 执行前　事务保存模型发出的 assistant.toolCall、规范化参数与稳定 operationId，再投递给 Runner。取回既有操作时校验会话、调用号和参数摘要。每次模型请求都从已提交的最后一条事件开始。
  • 等待时　工具桥可快速登记长操作。Pi 在本轮工具批次后暂停，界面显示等待。内部占位回执只供暂停控制。对话记录在真实结果到达时为每个 toolCallId 写入一份 toolResult。多个结果按原调用顺序配对。
  • 恢复时　收到最后一项真实结果后，由 Worker 新作业通过 runAgentLoopContinue 恢复。正在等待的创作轮次占用该聊天的活跃位，下一次输入可留在原草稿。视频受理后立即返回任务号并释放活跃位，渲染期间可继续聊天。
  • 并发验收　两个标签页同时发送或旧 Runner 晚回时，只有当前有效修订能推进状态。刷新不会把已经发出的工具调用再次交给模型生成。

说“改好这段词，再生两张图”，就能在同一条回复看到定稿和两张参考图。

Pi 把本轮要求和采用的素材版本交给同一个 Codex 工具。

  • 入口　普通问答由 gpt-6.1-sol 直接回答。用户明确要求改词时派 revise_prompt。明确要求生图时派 generate_images。要求两者时，第二步读取第一步返回的确切稿版。仅有文字描述的单独生图也可直接调用。
  • 授权　账号、项目、设备、工作目录和 Codex 配置从服务端的当前绑定取得。文本、历史稿、附件里的命令仅作为创作资料。Codex 的制作用途沿用改词和原生生图执行范围。
  • 回传　把稿件正文或可回读的全文引用、图版的顺序、名称、尺寸和稳定编号返回 Pi。聊天附件通过轻单已有的私有媒体接口打开。主模型按文字与编号识别资产。

当前 Runner 已能向绑定项目的 Codex 会话发送正文和参考原图。

改稿形成新稿版，上一版和用户固定的对白都能核对。

  • 输入　用户直接粘贴的文字、引用的聊天回复或指定稿版均可作底稿。按要求携带人物、固定对白、风格、画幅、用途和已选参考图。用户已定稿且要求直接出片时采用原文。
  • 改稿方式　普通文案按当前修改指令出一份完整稿。30 秒精修可在这一个工具任务内部复用镜序五岗与独立质检，逐岗传全文并核对时间覆盖、固定对白和角色约束。
  • 界面与失败　回传可复制全文、稿版号及来源。质检发现阻断问题时，给出对应镜头、原因和可修订的现有稿。要求改一个镜头时生成新版本，并把修改前的版本留在原回复。

两张图独立生成并按预留位置显示，先返回的图也有固定图号。

  • 派单　按用户要求先分配图 1、图 2 与各自的用途。每个位置一次有效原生生图操作。相同人物可将已完成的角色图作为下一张的明确依赖。重试以同一位置和操作号核对。
  • 验收文件　读取指定上游图版的实际文件送给 Codex。只接受该会话和轮次成功的原生生图项，并检查原图能解码、尺寸和哈希有效，再私有归档。只有文字或文件损坏时，标明该位置的失败原因。
  • 部分成功　图 2 先回来仍显示为图 2。图 1 失败时，显示它的重试入口，已经成功的图 2 可继续使用。若两张都依赖同一未完成的上游图，先等依赖就绪。
  • 交互　原回复直接渲染带图号的真实图片。点开后在当前页面看大图，用“上一张”“下一张”切换，按 Esc 回到消息，也可以打开原图。修改图 2 生成新图版，保留它与旧图版、底稿和来源素材的关系。

继续说“用第二张”，Pi 能找到上一轮的确切图版和采用的稿件。

“第二张”按用户正在引用的图组解析，图号与生成完成时间无关。

  • 识别顺序　优先使用输入框显式引用的图或回复。其次使用本轮明确点名的图组。自然语言省略来源时，用当前对话里最近一个明确展示或采用的相关图组。序号从 1 开始，基于当时的可见顺序。
  • 绑定时机　在接受这条用户消息时冻结它引用的消息序号、图组和显式选择。模型提出工具参数后，宿主据此解析和校验图版编号。后台回来的新图不会把已经选中的图挤到另一个位置。
  • 歧义　两个图组都可能是指代对象、图号越界、选中位置仍在生成，或找不到可用定稿时，在原对话列出具体候选或所缺项。等待回答期间，WAAO 提交次数为零。
  • 验收　上一条展示 A、B 两张图，下一条说“第二张”，提交输入必须恰为 [B]。再生第三张、刷新或在手机续聊后，显式引用原回复的第二张仍为同一文件。

用户可以选旧稿、替换一张图，也可以直接采用自带的定稿和图片。

  • 替换与恢复　修改任一稿件或图版均新建不可变版本。原回复可找到旧版和它关联的成片。新回复展示当前采用版本，用第二张重做时只替换新图组对应的位置。
  • 复用旧产物　支持从制作卡、当前画布、上传文件或同项目中有权限访问的旧回复明确引入资产，在当前会话建立来源记录。单纯切换项目或聊天不会自动选中其他对话的图。
  • 提示词重排　稿件保存原引用顺序。把原图 2 作为唯一输入时，将指向该图的引用编译为平台 @图片1。若稿件还要求已排除的图 1，先请用户补图或调整相应描述。用户指定的旧稿始终可回看。

关掉聊天再打开，仍能知道每件产物出自哪条消息。

  • 存储　聊天对象新增工具事件、产物索引和图组选用记录，关联现有制作卡及私有媒体编号。消息表继续保存轻单可显示的文字，原始媒体留在私有文件存储。聊天只保存一份图片的身份与版本关系。
  • 一致性　产物就绪、图组位置和消息附件引用在同一事务更新。文件可读且校验通过后再发布引用。重复回执按稳定编号识别。账号、项目绑定及聊天归属在读写时校验。
  • 上下文　发送给主模型的是所需稿件正文、候选图的顺序、名称、用途与版本。更早的图组可经明确引用回读。把大图文件直接交给 Codex 或 WAAO。聊天里展示私有缩略图和原图入口。

指定出片后，WAAO 收到定稿与选中的原图，任务号和成片都回到这段对话。

Pi 能通过 WAAO 工具提交成片，也能查询同一任务。

  • 生成意图　“用第二张出片”已明确表达提交意图。采用稿、图序、目标与计费归属都明确时直接提交一次。“先看看”“只改词”“出片要用哪张图”分别回答或预览。线上扣费任务只由本轮用户的明确生成要求触发。
  • 配置　从原输入框旁的“连接 WAAO”进入官网授权。Pi 通过 tools/list 发现工具，并可列出可写项目、画布、视频服务和可用积分来源；目标从本次会话或本机配置取得。只有关键信息缺失、指代不清或目标不匹配时才在原对话补齐。模型只拿到可选配置编号，凭据留在执行端。
  • 查询　“做到哪里了”按同一 operationId 或 taskId 查询。发现多个可能任务时按消息列出。明确“再出一版”才建立新的生成操作，复制旧稿图时也生成独立回执。

出片前逐项核对 WAAO 节点里的完整提示词、真实图与顺序。

  • 提交前　校验所选文件的哈希和归属。调用 asset_upload_start 获取上传凭据，按官网签发的 PUT 或 POST 地址发送原文件。asset_upload_complete 返回项目素材号后，以 canvas_apply_changes 写入图、视频节点和连线。按本次图序建立上游并映射提示词，设置目标模型、30 秒、画幅和计费来源。
  • 核对依据　调用 canvas_elements_get 回读画布，比较完整提示词、实际 inputs、连线、每幅图的 asset_id、时长、模型和积分来源。把实际节点快照连同稿版、图版、平台图号存回聊天操作，供用户在等待时展开。
  • 验收　示例采用 B 一张图时，平台只有一张对应 B 字节的上游，图号为 @图片1，生成请求恰好一次。图被漏传、顺序错、模型不支持该时长或计费来源不符时停在提交前。

网页 MCP 回读画布，核对输入和计费参数。

平台回传任务号后可以接着聊天，原片完成时回到原对话。

  • 即时反馈　提交中的等待行绑定原消息。平台确认后，真实任务号作为 waao.submit 的工具结果交回 Pi。Pi 可以回复用户，平台继续后台生成。已受理时打开原任务即可查看完整提交。
  • 长任务通知　按原任务号查询，终态事件只追加到来源会话一次。用户正在另一个项目时，原卡更新自己的消息。回到原聊天可看原片，后续问题也能引用这个任务。
  • 交付标准　先核对平台任务、节点、模型和原文件，再完整解码视频并记录时长，30 秒允许一帧误差。达标后显示播放器与下载入口。只有封面、无文件或时长异常时显示具体待核对项。
  • 停止　用户在送出前停止可取消后续步骤。WAAO 已受理时记录本地停止状态，并按原任务查回结果。仅凭平台明确的取消回执显示“平台已取消”。

已有交付路径可复用媒体校验和采纳版本关系。

刷新、掉线和版本切换后，已提交的任务沿原编号恢复。

刷新、重连和两端同时操作都只对应一次外部提交。

  • 消息与工具分层去重　复用现有发送 requestId。持久化的模型 toolCall 绑定唯一 operationId 和参数摘要，再申请执行权。用户要求两张相似图时，以两个明确的图位区分。重复调用同一操作返回原回执。
  • 异常恢复　Codex 启动回执丢失时按原 threadId、requestId、turnId 查回。原图已落盘而上传失败时继续归档。WAAO 请求超时按原操作号和节点查受理记录，未知状态只查询。确定失败后才允许按原因重试。
  • 隔离　交接前和写回时再核对账号、项目、聊天、设备绑定版本和授权代次。过期租约或另一会话的回执不能移动本轮。网页仅取获准媒体，密钥保存在各服务实际运行的位置。
  • 取消竞争　先持久化停止意图与修订，再中止本地执行。迟到回执可归档到它自己的操作，避免恢复已取消的后续步骤。切换模型、进程重启或浏览器断线都优先读持久化事实。

既有 Codex 派单记录支持登记和认领原轮次。

原有聊天、制作卡和已经受理的作业可以在升级后继续找回。

  • 迁移方式　加表、加可空字段和版本标识。旧纯文本消息照常展示与引用。只有有根据的 filmId、消息号或用户明确选择才能关联历史图组，避免猜测旧资产归属。旧业务稿件保持原作者、模型与文件来源。
  • 执行切换　每个正在执行的作业固定原引擎和外部操作号直至结束。新引擎接管启用范围内的所有新聊天消息。新工具命令与 Runner 上报能力协商，旧设备可继续原作业，并提示升级来执行新工具。
  • 异常与回退　Pi 模型故障时显示本轮失败，保留草稿与工具回执。发布回退只改变以后新消息的接入版本，已派出的 Codex、WAAO 操作继续核对，已有稿图和平台作业可读。
  • 兼容体验　旧记忆建议、待办验收、项目摘要和现有代码执行按钮沿用原权限。聊天里的制作进度可以打开详情卡。工具任务的回执优先交回发起它的 Pi 对话。

先在本机原聊天框验收普通对话、创作和按图提交，再决定云端迁移。

本机验收入口　在项目目录运行 npm run dev:pi，打开提示的「打开轻单.html」。在同一回复查看两张原图，放大图 2，刷新后重看。点击「连接 WAAO」完成官网授权并指定画布和积分来源，再用“用第二张出片”检验平台素材、任务号和原片。

  • 第一步交付　在原框普通提问，真实 Pi 工具循环产生可显示的主模型回复，外部工具调用均为零。对比旧入口的流式、取消、记忆和待办建议。
