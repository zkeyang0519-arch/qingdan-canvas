# 导航清理与运维资产设计

**目标**：按用户四项要求清理导航与旧验证流程，保留轻单功能，提供四种运维资产呈现方案。

**范围**：在现有 React / Workers 项目中直接做有明确要求的修改；不发布线上。现有大量未提交工作保留。

- [x] 将运维资产放到帮助和邀请协作之间；保留正式 Agent 模块和文字入口，移除机器人图标及独立 Agent 验证入口。
- [x] 移除专用 Agent 验证弹窗、试验组件和连接逻辑，保留共用协作、Runner 和诊断实现。
- [x] 重新设计现有表格的视觉层级，保留 CRUD、搜索、排序、状态/环境筛选、日期、部署和待办功能。
- [x] 基于官方网上案例制作四版独立交互设计预览：精密表格、产品目录、部署拓扑、到期时间轴。预览只用明确标注的示例数据。
- [x] 执行相关测试、npm test、npm run check、npm run deploy:check，并检查实际页面。

**设计取舍**：表格便于批量比较；目录便于辨认产品；拓扑强调产品与服务器的部署关系；时间轴强调日期与维护优先级。后三种为候选设计，选定后再接入真实资产操作。

**检查重点**：Agent 工作区可正常进入与恢复，待办增删和移回操作可用；仅旧验证流程退役；运维打开/关闭保持原工作区视图；日期与多服务器关系不丢失；只读模式不能编辑；窄屏可操作且无弹窗层级回归。

**用户澄清后的纠正**：恢复 Agent 文字入口、完整工作区、已保存的 Agent 视图、批次提醒与恢复，以及创建项目、新增/删除/移回待办的原有连接。顶部机器人图标、Agent 验证按钮及旧验证弹窗仍移除；运维资产位置与设计保持。42 项相关回归测试通过，类型检查与发布前构建通过，本地 8788 已返回恢复后的构建。纠正后的完整测试为 1414/1416；两项失败分别为旧体验服务测试的临时文件 rename EPERM 和 launcher 故意 SIGKILL 后等待端口释放超时，串行复核时这两项均通过（所在两文件合计 7/8 通过），但另一项 launcher 注册关闭标记检查失败（`agent-launcher-process.test.mjs:36`），单独复测也失败。该服务与测试文件本轮未修改，未扩大本轮改动去修复它；不能声称全量测试通过。
