采用用户已确认的方案：每条待办保存创建者，画布顶部的「作者头像」开关仅影响当前账号在当前画布中的显示，默认开启。个人画布继续可以邀请协作者。

- [x] 作者数据：保存账号 ID 和创建时昵称，服务端核定身份；编辑、勾选、撤销和恢复保留原作者；历史无法确认作者的条目显示「作者未记录」。
- [x] 同步与备份：保留作者字段，服务端确认不会产生重复提交或阻碍撤销。
- [x] 界面：复用昵称首字头像，画布与排列视图逐行展示；关闭后仍可在待办操作菜单、备注中查看作者。
- [x] 偏好：按账号和画布保存在浏览器中，默认开启，支持键盘操作。

升级兼容：首次创建作者表时读取历史回执和现存条目；缺少作者时，根据从第一版起连续的操作回执恢复最初创建者，无法证明的条目保持未知。旧客户端继续使用原消息格式，新客户端通过能力参数接收作者。作者表与对象版本、回执写入处于同一事务。

## 补充：上传头像图片

用户明确头像应使用上传图片，昵称首字只作为未上传时的默认显示。沿用当前账号、R2 和画布协作结构。

- [x] 账号设置提供上传、更换、移除头像；本地裁成 256×256，圆形显示，支持 PNG/JPEG/WebP/GIF，原文件限 5 MB。
- [x] 上传只修改当前账号；图片存 R2，D1 保存版本；本人及共享画布成员可读取。
- [x] 成员资料包含离线作者，通过画布消息更新头像；已有待办按作者 ID 显示最新头像，不修改作者归属。
- [x] 首页、在线成员、待办共用图片头像；加载失败回退昵称首字；原开关及查看偏好继续生效。
- [x] 验证上传权限、非法文件、替换移除、实时通知、离线作者、客户端显示和真实浏览器上传；运行完整测试与构建预检查。

补充验证：179 项测试全部通过，类型检查、构建与部署预检查通过。代码复查发现并修复图片处理期间切换账号的上传归属问题，上传请求始终绑定选择图片时的账号，失败不会使新账号退出。独立复查无遗留问题。浏览器实际验证 JPEG 上传及 256×256 输出、移除、无效图片提示、画布和排列中的图片头像、隐藏与刷新记忆。本地测试使用项目截图作为测试图片，未部署到线上。

升级时先应用 `0003_account_avatars.sql`，再发布；该迁移仅新增可空字段，回退旧代码可以保留字段。部署步骤见 `docs/cloudflare-setup.md`。

## 旧待办头像修复

用户反馈旧待办重写后仍没有头像，新建待办正常。排查确认头像已保存，但旧待办缺少创建者字段。本地 11 条旧待办均有完整的创建回执可证明作者。

- 在房间初始化事务中执行一次作者恢复，只使用从第一版起连续的服务端回执判断每条待办首次出现时的提交者；保留已知作者，历史不完整时不猜测。
- 快照和回执重放根据作者表补充元信息，不改写内容、对象版本或原始回执。后续正常编辑保存作者，重写及恢复不转移作者。
- 新增真实 SQLite 恢复测试，以及实际 Worker 升级、双作者、离线头像、重写、旧回执重放与历史缺失的回归场景。

修复验证：182 项测试全部通过，类型检查、构建和部署预检查通过。独立复查发现并修复接近大小上限的旧便签在补充作者时无法读取的问题；读取已保存内容时仅补作者，不重复执行写入大小校验，并保持字段顺序，避免额外同步。本地房间已自动完成作者恢复，改动继续保留在原目录且未提交。
