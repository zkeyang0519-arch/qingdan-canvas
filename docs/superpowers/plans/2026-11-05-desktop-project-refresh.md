# 轻单会话桌面显示修复

> 状态：**真实自动验收未通过，禁止标记为已实现。已撤下生产入口的默认刷新注入。** 初次对照出现侧栏条目未能在纯后台派单中稳定复现，不能作为可靠修复依据。

2026-11-05 后续实测：`9960d269-ede3-42eb-b892-f69eace899a0` 正常执行且后台刷新命令成功，但会话 `01a1a763-7b89-7761-a64e-48484256fa29` 仍未归组。完成后重试目录入口仍无效。官方 `codex://threads/<id>` 能打开真实会话，但不会完成项目归组。移动工具返回 `The task's source project could not be safely determined.`；将正式 app-server 项目来源补成唯一同目录项目后，桌面移动仍拒绝。当前程序接口不能证明能完成用户要求，未写入桌面私有状态。

目标：轻单派单创建真实会话后，自动通知 Codex 打开已授权的项目目录，从而让该目录的新会话进入桌面项目侧栏；不要求用户搜索。

实测依据：旧已归组与新未归组会话在 app-server 中均为 `projectId=null`，不能用后台项目字段冒充桌面归属。2026-11-05 新只读验收会话 `01a1a75a-eb4a-7923-9364-2e00b00c47e1` 创建后不在侧栏；调用官方 `codex app <root>` 后出现在「自然语言派单验证」下，桌面查询也返回对应项目 ID，当前聊天未切换。

方案：为 Adapter 增加可注入的桌面项目刷新回调，在确认真实轮次创建后异步调用。当前 Windows 本机入口默认启用；先检查既有协议注册，避免打开安装流程。只传已注册规范化根目录，使用 execFile 参数数组与超时。记录 requested/failed 状态，不能把命令成功当作 UI 可见证明；展示失败不影响任务结果，重放只重试刷新，不重发任务。
