# 第六步：轻单 Agent 聊天与记忆

用户选择独立模型 API，服务为 https://api.deepseek.com。采用 deepseek-flash + Chat Completions JSON mode，模型名可配置。服务端配置密钥，不复用 Codex 令牌；用户已在本机忽略文件 `.dev.vars` 中填写密钥，实际连接与完整聊天流程均已验证。

聊天按账号及项目 bindingId 隔离，先持久化用户消息再调用模型。一轮生成自然语言回复、可编辑的待办提案与记忆候选。用户点击保存提案后，通过第5步正式清单 API 写入；聊天本身不自动派单。每批最多50项，重复保存使用同一回执。

个人记忆适用于账号下各项目；项目记忆仅用于其 binding。面板可查看、手动新增、编辑、删除，也可从模型候选点“记住”。修改/删除使用版本检查、memoryEpoch 和来源墓碑，后续上下文排除被遗忘来源与衍生消息。正在生成的回复若记忆已变化则丢弃旧结果。聊天原文仍可查看；已确认保存的待办作为独立产物保留，不随记忆删除被改写。

“项目”指轻单的清单项目/分组（bindingId），不是本机目录。更换该分组的执行目录会保留其聊天与记忆；不同项目需另建分组。所有有绑定的修改请求携带bindingRevision并在服务端复核，旧提案同时绑定原授权；不会把旧页面写入默默转给新的目录授权。

采用每账号SQLite Durable Object，模型调用在持久排队后异步执行；不可把外部API回执不明的请求自动重复计费。超时/中断标失败，由用户明确重新发送。最多注入12条记忆、最近12条有效历史，当前输入优先，按整条丢弃旧背景保持预算。
