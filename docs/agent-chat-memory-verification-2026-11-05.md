# 第六步：聊天与记忆验收

2026-11-05，本机轻单使用用户配置的 DeepSeek 独立 API（`deepseek-flash`）完成验收。没有发布线上版本。

## 体验入口

打开本机 `http://127.0.0.1:8790/?room=5f3a319b-8f98-404c-b58e-792553a6ea89`，进入 **Agent 验证 → 6 · 聊天与记忆**，选择 **第六步聊天记忆测试**。聊天记录保留在该清单下；3项待办可在同一清单的第5步查看。

## 真实模型验收

| 操作 | 观察结果 |
| --- | --- |
| 自然语言提供三个有依赖的待办 | 返回自然语言说明及按顺序排列的3项可编辑提案 |
| 修改第一项标题并保存 | 正式清单显示修改后的标题、执行要求和完成标准 |
| 重复保存同一提案 | 清单仍只有3项，返回同一批待办编号 |
| 提出个人偏好、项目要求候选并采纳 | 两种范围的记忆都可查询和使用 |
| 不提供值，仅询问已保存记忆 | 回答正确的两条测试值 |
| 修改个人记忆后再次询问 | 使用新值，不带旧值；项目记忆仍可使用 |
| 删除个人记忆后再次询问 | 明确没有该记录，仍能回答项目记忆 |
| 删除剩余测试记忆 | 只删除本次创建的2条测试记忆，没有把验收值留作用户偏好 |
| 重启本机服务 | 11条聊天消息、3项待办与记忆删除结果均保留 |
| 浏览器界面核对 | 第6步显示自然语言对话、已保存提案和已删除记忆提示；“打开第5步”进入同一清单并显示3项可派单待办 |

保留的待办依次为：

1. 01 · 创建验收文件（已核对提案）
2. 02 · 追加第二行
3. 03 · 核对两行内容

三项均保持未完成状态，执行记录为0。聊天提案需先保存到清单，再由用户在第5步提交批次。已有的批次模式不变：一次提交在同一个 Codex 会话依次执行，下一次提交另开会话。

## 自动化与兼容性验证

- `npm test`：699/699通过，使用隔离测试数据。
- `npm run check`、`npm run runner:check`：通过。
- `npm run deploy:check`：本地打包和Worker部署预检查通过，没有实际发布。
- 覆盖跨账号及清单隔离、记忆版本冲突、遗忘期间的在途回复、旧候选不能恢复已删除记忆、提案保存幂等、未决保存只读核对及完整载荷匹配。来源失效且暂未查到回执时仍保留只读核对入口，可发现迟到的真实保存结果，不再发起新写入。

聊天原文仍可查看；修改或删除记忆会使旧来源不再进入后续模型上下文。已明确保存的待办作为独立结果保留。“项目记忆”按轻单清单或分组区分，改变该分组的执行目录不会清空其聊天和记忆。
