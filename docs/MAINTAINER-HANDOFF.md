## 先了解当前状态

- 本仓库是独立的轻单协作画布，包含网站、Windows Electron 轻岛、本机 Agent 与 Tauri 轻量版；不是父目录中的另一个项目。
- 日常开发分支为 `feat/qingdan-mcp`，生产分支为 `main`。沿用这两个分支，不为接手擅自重命名或覆盖生产历史。
- 源码 `package.json` 为 `0.3.12`。2026-11-27 查询 GitHub Release，最新正式版本为 `v0.3.11`，最新轻量预览为 `qingdao-preview-v0.4.0-preview.5`。`0.3.12` 仍是待发布代码 / Beta 验收阶段，见 [版本说明](qingdao-release-0.3.12.md)。接手时应重新核对，不能只按源码版本判断线上版本。
- 网站生产与预览环境的 Agent 仍受开发门控；完整 Agent 在本地使用。不要通过修改旧功能开关绕过此边界。
- 本次交接只整理、提交并推送开发分支。网站部署、远程 D1 迁移、正式标签、安装包发布和账号所有权转移是独立操作。
- 最近工作和验证范围见 [改动清单](handoff/2026-11-27-changes.md)。历史设计稿在 `docs/superpowers/`，其中的目标与示例不能当成已经实现的功能。

## 接手第一天

1. 阅读根目录 [AGENTS.md](../AGENTS.md)，确认工作目录、分支及发布要求。
2. 从 GitHub 克隆开发分支到新目录，不复制原维护者的整个浏览器档案或运行数据来代替安装。
3. 使用 Node.js 24+，执行 `npm ci`。Runner 的 Codex 版本要求以 [protocol-version.json](../runner/protocol-version.json) 为准，目前为 `0.167.0-alpha.4.1`；Pi 对话连接器的自动探测不等于 Runner 可以忽略版本要求。
4. 执行下面的离线业务回归与构建检查，再启动本地服务。

```powershell
git clone --branch feat/qingdan-mcp https://github.com/zkeyang0519-arch/qingdan-canvas.git
cd qingdan-canvas
npm ci
npm test
npm run check
npm run runner:check
npm run deploy:check
npm run dev
```

主入口为 `http://127.0.0.1:8790`，底层 Worker 为 8788；`npm run dev` 自动构建并应用本地 D1 迁移。`npm run dev:pi` 是单独的试用入口，不能把它的账号、OAuth 回调和状态与主入口混用。测试使用临时目录、模拟业务服务与独立数据库；不要让测试指向真实的 `.wrangler` 数据或正在使用的设备绑定。

5. 用接手者自己的账号检查登录、画布同步、项目聊天、任务卡确认、问题回答、停止任务以及模型连接编辑 / 删除。注册邮件需要配置，见 [.dev.vars.example](../.dev.vars.example) 和 [部署说明](cloudflare-setup.md)。
6. 在设置中配置可用主模型、Codex 与 WAAO。WAAO 须完成轻单自己的 OAuth，确认服务端账号并开启项目服务。不要从 Codex 复制其托管令牌。
7. 有任务运行时不重启。源码服务先执行 `node scripts/agent-install.mjs diagnose --source`；确认活动与未知任务均为零后才安全停止，再用 `npm run dev` 启动。已安装服务按 [安装与故障恢复](agent-installation.md) 操作，不要把源码入口与已安装入口同时启动占用端口。

## 发布与回退

网站发布遵循 [Cloudflare 配置与升级](cloudflare-setup.md)：先核对环境与数据库，应用必要迁移，再按维护者授权发布代码。已有迁移不重命名，生产 / 预览资源不混用。`npm run deploy:check` 只构建和 dry-run，不会证明线上已经升级。

桌面按 [升级验收](workspace-upgrade-acceptance.md) 和 [AGENTS.md](../AGENTS.md) 执行：

1. 明确正式、Beta 或轻量版渠道；先在隔离目录 / 一次性 CI runner 验证安装、自动重启、草稿、账号、绑定与回执。
2. 正式版提升版本并验证签名、安装包、blockmap、更新清单与打包内容。运行中的任务或保存失败时不能强行升级。
3. 同步官网下载页的版本、对应平台安装包与更新说明，再运行该渠道的在线下载页检查。仅 GitHub Release 存在不算完成发布。
4. 在部署记录中写入提交、版本、环境、验证范围和回退方案。`deployment-status.md` 是带日期的历史记录，不能当作实时监控。

`desktop-update-acceptance.yml` 目前只手动触发；Tauri 分支构建仅产出验证 artifact。不要为了交接推送一个正式标签或触发生产部署。本次整理不执行这些动作。

故障时先停止新增派发、保存草稿与原回执，确认运行状态后恢复已知兼容版本。不要通过删除 D1 表、整个 `.tmp`、用户目录或任务账本来“重置”。已经受理但结果未知的操作先查询原任务，尤其不能自动重新提交 WAAO 生成。
