## 故障与回归覆盖

持久化 SQLite 恢复测试覆盖：派单保存后丢投递、初始和第二项原生启动应答丢失、启动标记保存后未发送、applied ACK 丢失、事件 ACK 丢失、执行报告 ACK 丢失、推进许可 ACK 丢失、清单写回成功而 ACK 丢失、终态报告丢 ACK、未知 thread 身份阻断。断点重建云端存储对象和 Runner 控制器，检查实际原生模拟进程调用计数，而不依据模型文本判成功。

修复报告版本在 queue.observe 中提前持久化的窗口：终态已保存但报告回执尚未保存时崩溃，重放原来被旧版本规则忽略，导致持有执行权无法释放。报告版本与回执现在一起提交，故障回归先失败后通过。

过期租约恢复需要用户在原暂停批次显式发起。服务端核验原派单、原租约身份、已验收回写及下一轮尚未取得许可；本机再次核对完整原生历史没有活动轮次、清理后台进程、确认 Git 与目录锁不变。恢复确认采用先持久化固定到期回执再续租的顺序，丢 ACK 或两份存储之间崩溃不会再次延长同一票据。恢复不会自动推进下一项。显式停止意图在任何异步操作前持久化并按命令编号关联，无论租约已过期还是仍有效，崩溃恢复都不能越过用户停止。相关成功、丢回执、活动轮次、缺失回写、错误轮次、云端取消及停止崩溃测试已覆盖。

安装审查修复了 Windows 路径大小写、退出早于控制回执、控制桥在线误判应用就绪、旧 PID 文件锁并发回收与空锁、PowerShell 中文路径编码、空/残缺控制密钥被复用。生命周期改用 SQLite 事务互斥；密钥在安装发布、启动、控制客户端和桥接两侧均校验完整格式，损坏文件保留并报错。独立复审未留下 P0/P1/P2。

## 验证范围

不重复保证针对同一持久化派单、同一任务推进许可、原生 turn 启动及清单回写。未知原生是否接受、无法唯一匹配历史、仍有活动轮次或后台进程时保留占用并阻断，不能依据固定超时重新执行。模型内部脚本及外部系统副作用不在通用 exactly-once 保证之内。

普通 `stop/restart` 遇活动或未知任务会拒绝，包括尚有剩余事项的暂停批次；`--interrupt-active` 明确中断，可能取消剩余待办。本次任务间终止进程是故障注入，不能描述成普通 restart 自动续跑。没有执行整机断电、Windows 开机自动启动或远程生产验收。
