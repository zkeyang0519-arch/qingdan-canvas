# 在轻单 Agent 中制作 30 秒短片

## 本机试用原聊天框

在项目目录运行 `npm run dev:pi`，然后打开启动时列出的「打开轻单.html」。原聊天框通过本机 RPC 把消息交给原版 Pi 1.5.2，初始主模型为星驰的 `gpt-6.1-sol`。在「设置 → 主模型」查看当前连接，选择后点击「应用到当前对话」才会切换；新对话默认模型单独保存。新建连接不会自动切换主模型。「添加 DeepSeek 官方连接」预填官方地址与 Flash、V4 Pro 模型，密钥由用户在界面填写，使用官方 [Responses API](https://api-docs.deepseek.com/api/create-response/)。每条消息在发送时固定所选连接；失败消息旁的换模型重试沿用原消息及已有工具回执。

试试“把这段词改好，再生两张参考图”。Codex 返回的图片直接显示在回复里，点图可放大、切换或打开原图。刷新同一聊天后，图号仍对应原来的文件。

首次启动会在项目根目录生成 `.dev.vars.pi`。把星驰密钥填到 `XINGCHI_API_KEY=""` 的引号中，保存后刷新聊天页即可。密钥留空时仍可查看已有对话和图片。本机服务按轮读取密钥并交给 Pi 子进程，由 Pi 向 `https://api.xingchiapi.com/v1/responses` 发送请求。Pi 根据自己的版本和运行环境生成 `User-Agent`，轻单前端标识放在 `X-QD-Client: Qingdan-Agent` 请求头中。如果星驰返回 `client_not_allowed`，原聊天框会显示这一拒绝原因并结束本轮。账号发布的模型别名如有差异，可在同一文件调整 `QINGDAN_PI_MODEL` 后重启本机试用。[星驰 API](https://api.xingchiapi.com)

轻单在本机保存账号、项目绑定、聊天权限、工具执行记录和原图。Pi 获取当前消息、这段对话中可见的历史、已采纳的记忆和可引用的素材编号。Codex 和 WAAO 的执行权限由本机服务逐轮核对。[Pi 官方 RPC 说明](https://docs.pi.dev/latest/rpc)

出站模型请求采用 OpenAI Responses API。Pi 将可见的用户消息和助手回复按原顺序放进 `input`，并在 `tools` 里声明本轮可用的专用工具和项目勾选的 MCP 工具。模型返回 `function_call` 后，Pi 使用同一个 `call_id` 将工具结果作为 `function_call_output` 回传，再把最终回复显示在聊天框里。[OpenAI 工具调用规范](https://developers.openai.com/api/docs/guides/function-calling)

在输入框旁打开「工具 → WAAO」，可直接使用本机 Codex 已配置的 WAAO；使用独立网页授权时点击「连接 WAAO」。回来后点「选用项目查询工具」可查询项目。要按图号和定稿出片，点「选用短片制作工具」启用制作流程所需的工具。随后可以在同一聊天里说“列出 WAAO 项目”，指定项目、画布、模型和积分来源，再说“用上一组第二张图和刚才改好的词出片”。授权与查看画布都不会创建生成任务。图 2 作为唯一上游时，对应 WAAO 节点的 `@图片1`。平台受理后，轻单显示平台任务号。继续问“成片好了吗”，就绪后可以在对话中播放。历史 `LOCAL-` 回执标记的是较早的本机模拟试验。

WAAO 的执行端是官网提供的 Streamable HTTP MCP。Pi 通过 `tools/list` 核对本次授权可用的工具，调用 `asset_upload_start` 获得签名地址，送入选中原图的字节，再调用 `asset_upload_complete` 取得项目素材编号。轻单通过 `canvas_apply_changes` 写入定稿和素材连线，通过 `canvas_elements_get` 回读校验，然后用固定幂等键调用 `node_generate`。任务进度来自 `task_get`。本地试用设置与模块验收见[统一 Pi 对话审阅方案](./superpowers/specs/2026-11-19-unified-pi-agent-review.html)。[WAAO MCP 官方资源说明](https://www.waao.studio/.well-known/oauth-protected-resource/api/mcp)

## 原有短片制作卡入口

进入开发或测试环境的「Agent → 项目聊天 → 短片制作」。桌面沿用项目导航、项目聊天和待办与执行三块区域，手机沿用原有页签。未绑定设备也可保存制作卡。绑定当前项目的 Runner 后，从卡片开始执行。

**DeepSeek 是主控，Codex 负责改提示词和生参考图，WAAO 负责出片。** 轻单接收要求、派发步骤、保存各版产物和平台回执。DeepSeek 通过 Pi 理解简报、默认写初稿并整理素材清单。Codex 使用镜序五岗规则逐次改稿，并用独立轮次质检。做视频时，Runner 把采用的定稿和按顺序排列的真实图片上传到选定的 WAAO 项目，在同一视频节点提交整片。

## 用同一张卡完成不同目标

| 目标       | 操作                                                                                           | 交付依据                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 初稿       | 填简报并选择初稿来源。DeepSeek 为默认，也可以在本次指定 GPT 或 Codex                           | 可重新打开、复制和编辑的完整稿件，有来源与版本                                               |
| 拍摄提示词 | 选初稿或先起草。DeepSeek 派 Codex 按五岗精修并独立质检。用户提供的最终稿可以直接采用           | 每岗全文、定稿、0–30 秒镜头、质检结果及对应的 Codex 会话和轮次。遇阻断问题可按岗位修改       |
| 参考图     | 写静态描述，上传原图、从当前画布选图，或对已有图片点「重做这张」                               | Codex 用原生生图工具生成参考图。设备读取该轮原图，解码、校验后归档，记录用于生成它的具体图版 |
| 30 秒成片  | 选定定稿、真实图版及顺序，核对团队、画布、模型和计费来源后生成。已有定稿与图可选择「直接出片」 | WAAO 同一视频节点的整份提示词、有序上游和平台任务号，以及经完整解码和时长校验的原文件        |

新建卡时可以直接写“用 GPT 起草，只给我一份拍摄提示词”。表单会据此选中初稿来源和交付目标，也可以手动调整。手动选择会保留。编辑简报或关闭抽屉都不会启动生成。

已绑定设备时，点所选目标对应的按钮就能建卡并开始制作，也可以点「保存制作卡」先存简报。自带定稿和图时，先存卡、导入素材，再点「生成 30 秒成片」。正在制作时可以编辑下一版。「保存工作版」保存要求和选择，「生成新版成片」才开始新一版视频。卡片按版本保存稿件、图片、外部任务号及交付文件，聊天中引用的版本可再次点开。原待办的完成由用户在交付后验收。

## Runner 配置

在启动**绑定的 Runner 进程**的环境中配置所需服务，并在配置变更后重启该 Runner。Node.js 24 或以上，运行 `npm ci` 后用 `npm run runner:build` 构建。模型会话使用随项目锁定的 Pi 0.83.0。图像和视频验证使用设备 PATH 中的 `ffmpeg` 与 `ffprobe`。

| 服务             | 设备环境变量                                                                                                                                                             | 使用范围                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| DeepSeek / Pi    | `DEEPSEEK_API_KEY`                                                                                                                                                       | 模型 `deepseek-v4-pro`。在卡内展开「设备制作服务」可以发起只读工具验证，结果和最近验证时间显示在同一设备的服务信息内                             |
| Codex 改词与质检 | 使用运行 Runner 的系统账号已登录的 Codex。可用 `QINGDAN_FILM_CODEX_BIN` 选择短片专用程序，缺省沿用 Runner 的 Codex。可用 `QINGDAN_FILM_CODEX_MODEL` 指定该连接可用的模型 | 制作连接支持项目固定的 0.167.0-alpha.4.1 和 0.169.0-alpha.11.1。每个岗位在独立会话里按本岗要求修改上一稿的全文。轻单保存最终改稿和对应的轮次编号 |
| GPT 初稿         | `QINGDAN_GPT_MODEL` 与 `QINGDAN_GPT_API_KEY` 或 `OPENAI_API_KEY`。兼容服务可指定 `QINGDAN_GPT_BASE_URL`                                                                  | 本次选择 GPT 初稿时调用。默认连接地址为 OpenAI 的 `/v1`                                                                                          |
| Codex 专项       | 沿用本机 Codex 和项目执行绑定                                                                                                                                            | 通过现有执行服务以只读权限整理项目文稿。父卡记录专项任务编号并接收该轮正文                                                                       |
| Codex 生图       | 同一 Codex 连接，所用账号及模型需有原生生图权限。设备按 `codex features list` 报告本机图像功能                                                                           | 以所选图版的真实文件作为输入，从该轮成功的 `imageGeneration` 回执读取原图。回执只有文字时会显示具体缺项                                          |
| WAAO 网页 MCP    | 本机 Pi 聊天使用「连接 WAAO」进行 OAuth 授权，或由操作者配置该资源签发的 `QINGDAN_WAAO_MCP_TOKEN`。独立 Runner 使用此环境变量                                            | 连接官网 `https://www.waao.studio/api/mcp`。Windows 本机试用使用凭据管理器保护授权记录。凭据仅用于与签发方及其 MCP 通信                          |
| WAAO 目标        | `QINGDAN_WAAO_PROJECT`、`QINGDAN_WAAO_CANVAS`、`QINGDAN_WAAO_MODEL`、`QINGDAN_WAAO_BILLING`；使用组织积分时填写 `QINGDAN_WAAO_TEAM` 为组织编号                           | 项目号与画布号分别取自官网。计费来源为 `personal` 或 `org`，兼容旧设置的 `team`。本机对话还可查询并指定组织下某个团队的预算                      |

卡片显示设备报告的配置状态，以及最近一次有回执的服务和阶段。尚未真实调用的服务仅显示配置状态。服务密钥在本机读取。浏览器及项目记忆只保存创作内容和可显示的连接信息。

## 版本和恢复

- **只看稿或只看图。** 在出片设置中选择预览停点。到达停点后，稿件或图片先归档，点击「采用并继续」才推进。
- **只换一张图。** 在原图点「重做这张」，新的图版记录原素材和用途。已有成片继续引用当时的图版，后续出片可采用替换后的有序图集。
- **掉线或回包缺失。** Worker 保存每版输入、阶段和执行权。本机 SQLite 记录阶段结果、上传进度、外部操作和待回传回执。平台是否受理未知时，卡片提供「核对原提交」。只有明确发起新版才分配新的出片操作号。
- **Codex 回包缺失。** 轻单在派发前持久化会话和请求编号。轮次开始后补记轮次编号，恢复时用相同请求定位原轮次。新制作使用协议 2。已开始的协议 1 版本沿原执行路径恢复，保留历史文稿、图像来源和已受理的平台任务号。新版 Runner 可处理这两种制作记录。
- **核对 WAAO 交接。** Runner 写入并回读 WAAO 视频节点后，打开本版的「WAAO 节点上的提示词与素材顺序」，可查看完整提示词、每个 `@图片N` 对应的图版与平台素材编号。平台受理后，任务号显示在同一处。等待出片、刷新页面或设备离线时均可查看已经保存的记录。
- **停止。** 已受理的 WAAO 任务继续按原任务号查询。卡片分别展示本地停止后续制作和平台交付结果。
- **媒体验收。** 图片归档上限 16 MiB，视频 256 MiB。读取归档视频支持 Range。设备验证首个视频流、完整解码到结尾，并把实测时长记录到版本中。30 秒的允许误差为该视频一帧。
