# 第 4 步：MCP 派单

运行 `npm run dev:agent`，登录 [本机轻单](http://127.0.0.1:8790)，进入画布后打开右上角 **Agent 验证 → 4 · MCP 派单**。需要先在第 3 步绑定电脑。

## 体验路径

1. 在 **新建项目名称** 填写名字，例如“个人网站”，点击 **创建项目**。文件夹最后一级和项目显示名都使用这个名字。重复创建同名项目会保留文件和会话，不同名称使用独立的目录与派单记录。
2. 为每条待办填写 **执行要求** 和 **怎样算完成**，用 **添加待办** 增加条目，用上移/下移排好执行顺序，然后一次点击 **提交批次**。
3. 一次提交只创建一个 Codex 会话。Runner 按顺序逐项发送，每项单独一轮；收到当前项有效的 done 回执后再发送下一项。派单记录显示当前项、每项结果和统一会话入口，关闭网页后本机 Runner 仍继续执行。
4. 批次遇到阻塞、无效结果或需要信息时暂停。补充说明会留在原会话，处理当前项后再继续剩余条目。审批/交互等待不会被当作完成，也不会自动跳到下一项。
5. 所有待办结束后显示 **批次执行完毕，待你验收**。下一次提交会创建新的批次和新的会话；已完成或已停止批次不追加新任务。执行中可 **请求停止**，确认当前轮及其后台命令已停止后，剩余项才标为已停止。

也可以选择第 3 步已经关联的正常清单项目，并填写自己的执行要求。**只总结项目**创建独立的只读总结会话。提交后关闭界面不会撤销任务；本机 Runner 仍需保持运行。

新项目名称支持中文和空格，最长 60 个字符；不能填写完整路径、路径分隔符或 Windows 保留名称。项目保存在程序管理的账号专属目录中，可展开 **查看本机目录** 检查实际文件。旧版目录和会话不会被搬动，在 **独立测试项目** 中继续查看；新建的命名项目会单独列在选择框中。

**创建项目**只准备目录和轻单关联；**提交批次 / 只总结项目**才会新建 Codex 会话。批次模式暂不要求桌面侧栏归组，使用轻单的派单记录查看进度或打开对应会话。此前未通过实测的目录刷新功能保持停用。

新派单和补充说明只把当前任务原文放进 Codex 的用户消息，例如“创建 hello.txt，内容为……”。完成标准、项目背景和执行规则通过独立上下文传入，不拼接到聊天正文。账号、绑定编号、哈希和请求身份保留在协议字段与本地日志中。

新会话通过 `qingdan_report_result` 工具提交结构化回执，最终用自然语言说明结果。Runner 在轮次结束后读取完整记录，核对回执位于最新用户要求之后，再补全当前待办的真实编号。每轮只传当前项的执行要求与验收标准，未来条目不会提前交给模型。旧会话保留原消息与 JSON 结果兼容方式，旧单条接口也继续可用。

第 4 步提供手动批次派单、批次内顺序执行、查询、补充与停止。第 5 步 **真实清单** 已接入真实待办保存、排序、来源绑定和完成状态回写，见 [第五步验收](agent-checklist-verification-2026-11-05.md)。聊天整理待办和跨批次调度仍属后续工作。每批最多 50 项，同时受不可变快照大小和现有执行时限约束。当前遇到审批/交互输入会显示等待状态和问题，可以请求停止，不会自动批准。

## 接口与授权

独立入口为 `/executor-mcp`，使用固定版本 MCP SDK 的无状态 Streamable HTTP。现有画布 `/mcp` 的 OAuth 凭据不具备执行权限。

| 工具                  | 用途                                   |
| --------------------- | -------------------------------------- |
| `codex_list_projects` | 查询指定已授权设备的项目与缓存会话信息 |
| `codex_create_run`    | 提交已经获得授权的不可变执行快照引用   |
| `codex_get_run`       | 查询进度与按序分页的事件               |
| `codex_continue_run`  | 在指定轮次上补充说明或继续原会话       |
| `codex_cancel_run`    | 请求停止；等待本机确认                 |

界面的操作通过同一 MCP 传输完成。登录账号通过明确提交操作先生成执行意图；内部短期凭据限定账号、设备、项目绑定版本、设备授权版本、用途和入口，不返回给浏览器。模型不能指定任意本机目录或凭据。

云端先持久化派单记录，再向设备交付。设备先获得项目锁和租约、核对快照并记入本地日志，再调用已有 Codex 适配器。相同请求编号可重试，相同编号改变内容会被拒绝。执行是否已启动无法确认时，保留待核对状态，不自动再开一个会话。

生产环境默认关闭派单；本机体验启动器显式启用。测试使用独立 workerd、临时数据库与假 Codex；真实验收另外通过本机已登录的 Codex 执行测试项目。
