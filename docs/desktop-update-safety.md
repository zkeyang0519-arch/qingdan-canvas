# 轻岛首次迁移与发布验收边界

## 数据接续

桌面更新复用完整 Chromium profile，不能只复制 Cookies 或 IndexedDB 文件。旧源码 profile 保留在原路径，`%APPDATA%/Qingdao/profile-location.json` 只记录该目录位置；安装器不搬动或删除它。首次全新安装则使用 `%APPDATA%/Qingdao/profile`。因此已经迁移的旧项目目录仍是数据存储位置，不能随意删除。

旧源码用户首次安装前，在原项目运行：

```powershell
node scripts/desktop-register-profile.mjs
```

该命令不读取凭据、不复制正在使用的数据库，也不会退出窗口。它只注册当前项目已有的 `.tmp/desktop-profile`。若已经存在正式档案登记，它会保留该登记；若登记的原目录不可访问，程序停止启动并提示恢复原目录，不能悄悄创建一个空白账号档案。

首次安装前须先保留旧版窗口中未提交的输入，然后从托盘正常退出旧版。尚未带持久化功能的旧进程，其纯内存输入无法被安装器或新版本追溯恢复。本次版本开始，未提交输入按来源、账号、画布和项目分别保存在 profile 中。后续更新先确认保存成功，刷新 Cookie 与存储，再安装重启。

`QINGDAN_DESKTOP_PROFILE` 用于隔离验收，不会改写正式档案登记。`QINGDAN_DESKTOP_SOURCE=1` 可让开发入口继续使用源码运行时。正常启动优先选择固定的当前用户安装路径 `%LOCALAPPDATA%/Programs/Qingdao/Qingdao.exe`；已经运行的旧本机服务通过源码主入口的转发逻辑，也可以进入已安装版本，不要求停止 Agent/Runner。

## 发布与测试的区别

网页启动使用两条本机路径：安装版自身提供 8791 端口和 `qingdao://open` 协议，不依赖开发服务；已有开发服务的 8790 端口可检查、下载安装包。两条路径均继续使用精确 Origin、Host、请求标记和原有一次性交接校验，不向网页暴露 Cookie。安装包来源固定为本项目 GitHub Releases，网页不能指定 EXE、安装参数或执行命令。

启动器的本机安全退出接口使用 profile 中的随机能力令牌和实际运行 PID；拒绝带 Origin 或浏览器请求标记的直接调用。下载与 SHA-512 校验在退出前完成。保存失败、无法确认进程已经退出或检测到重新打开的进程时，不启动安装器。NSIS 自身也拒绝强制终止正在运行的轻岛。

网页发起更新时，在旧窗口完成保存并退出后，安装步骤会完成，即便原网页标签页关闭也不强制终止安装器；本机启动器随后恢复最后保存的画布，不复用已取消的账号交接。首次没有任何本机软件时，网页只能引导下载，用户必须手动运行一次安装包，不能绕过浏览器或 Windows 的授权界面。

本地生成 EXE、单元测试通过、隔离 profile 重启成功，分别证明打包、逻辑和存储接续能力；它们不等于 GitHub 自动更新源已经发布，也不能代替两个正式版本之间的真实下载和安装验收。

正式发布由 `.github/workflows/desktop-release.yml` 处理。标签须与版本号一致、来自 main，并且更新源可匿名读取。用户当前选择未签名发布，Release 说明必须标注这一点；下载仍验证包的 SHA-512，但该校验不能替代发布者签名。将来配置签名或设置 `QINGDAO_REQUIRE_SIGNING=true` 后，缺失或无效签名须阻止发布，不能自动退回未签名。不能将 GitHub Token 或证书放进客户端。

公开更新闭环的验收应记录：旧安装包与新安装包版本、是否签名及发布者（如有）、更新源地址、下载校验结果、重启结果以及登录、待办、未提交输入恢复结果。有效登录会话可保留；已过期或服务端已撤销的会话仍应要求重新登录。
