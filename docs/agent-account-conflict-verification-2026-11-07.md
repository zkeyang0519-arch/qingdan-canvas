# 电脑绑定测试账号导致无法连接的恢复验证

## 实际故障

用户继续反馈“电脑未连接”。本机服务和执行轮询正常，但通过用户实际打开的 VS Code 内置浏览器查看 8788 页面，电脑设置中的精确错误为 `Runner belongs to another owner account.`。

只读核对设备配置与本地应用账号元数据后确认：设备仍属于之前真实验收创建的“Agent 体验验证”测试账号，网页登录的是用户的实际账号。账号隔离正确拒绝请求，前端却将此错误当成断线，设置页还错误建议启动服务。上一轮只验证了服务就绪与协议读取，未完成用户实际登录态的配对验证。

## 恢复过程与边界

1. 两次确认活动执行数为 0、未知执行状态为空，旧设备 `leases` 为空；通过受管停止流程完全退出服务，未强制中断任务。
2. 核实旧绑定确为该测试账号，使用经过绝对路径与重定向检查的文件操作，将整个 `.tmp/runner-device` 归档为 `.tmp/runner-device-agent-trial-backup-20261107`。保留原数据库、执行记录和 Windows 凭据，未改动全局工作区锁。
3. 归档只读复核：一个执行日志数据库中不存在 `state.key='held'`，设备租约仍为 0。
4. 启动空设备状态，通过当前用户已登录的网页完成正常配对。未迁移旧测试账号的目录授权或项目绑定。
5. 实际页面显示“我的电脑 / 在线”，会话选择器成功列出 50 条真实 Codex 会话及“加载更多会话”。页面停在选择器，未替用户选择项目，也未启动执行任务。
6. 只读复核新的设备 owner 与当前画布 owner 一致、配对已完成、远端心跳及时，当前新设备目录授权与租约均为 0。

旧云端测试设备将呈现离线，未将其描述为已撤销。应用账号、画布、聊天、项目文件和旧执行状态保留。脱敏运行结果见 `.tmp/agent-account-conflict-runtime-2026-11-07.json`。

## 代码修复

- 原有 owner 校验不变；绑定其他账号时返回明确的 `OWNER_MISMATCH` 和中文说明。
- 本机 API 仍返回 403，仅增加固定错误码，不返回旧账号身份、目录或凭据。
- 客户端保留错误码与 HTTP 状态，工作区显示“电脑账号不匹配”，设置页显示“电脑绑定账号不一致”，不再误导用户启动已运行服务。
- 账号冲突时绑定按钮仍禁用，不允许网页自动接管其他账号的设备。
- 工作规范补充实际验收隔离要求，避免测试账号占用用户设备身份。
