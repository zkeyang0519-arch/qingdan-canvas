聊天提案确认保存后直接刷新清单；真实清单支持编辑要求和验收条件、上移/下移、选择任务、权限设置和批次提交。一次提交一个 Codex 会话，后续项目任务依次执行；下一次提交新建会话。运行进度复用既有暂停、继续、停止、验收、异常处理与原生审批/提问机制。

草稿与待核对请求 ID 使用当前标签页的 sessionStorage，按账号、画布、项目、绑定版本隔离，聊天另按聊天 ID 隔离。恢复草稿不发送消息或创建批次。摘要和记忆抽屉不卸载聊天；原生请求使用 portal，窄屏隐藏任务面板时仍可显示，上层审批优先处理 Tab/Escape。已查看项目的后台待处理请求仍有返回准确批次的入口。

## 验收发现与修复

1. **新回复错误过期：** 实际模型返回成功，但提案被标记 stale。`ChatStore.replyJob` 丢弃了上下文的 `provenance.project`。保留该字段，隔离 Workerd 回归验证新回复可采用、摘要更新后的旧回复仍失效。旧记录缺少来源字段时继续安全地禁用，用户重新生成后可保存，不猜测或回填来源。
2. **批次目标与历史切换：** 在进行队列操作时收到新提交目标，曾让新批次一直禁用；等待当前操作收尾后切换准确目标。只对新收到的目标切换，避免查看历史后跳回初始批次。多项目提醒按项目保留。
3. **跨项目重复新增：** 独立审查发现新增待办已提交后丢回执或立即切项目，恢复草稿重试会生成新请求 ID。回归复现两种场景后，把待核对请求身份与草稿同范围保存，只有当前组件确认应用后清除；重试复用原 ID。
4. **原生弹窗焦点：** 独立审查发现先开的抽屉会抢走后来审批的键盘事件。回归验证 Tab 留在上层审批、Escape 只关闭审批并恢复底层焦点；底层抽屉在原生弹窗期间让出键盘处理。
5. **设置目录默认值：** 实测发现默认选择首个允许目录，容易误改绑定。修为优先选当前关联目录，用户明确选择其他目录时保留其选择。设备面板回归验证默认值与确认后的通知。

每项逻辑修复均先观察失败再验证通过。独立审查的两项重要问题已修复，没有遗留次要问题；审查未评估前八步整体后端和部署，本轮单独完成浏览器呈现验证。
