# Runner 设备绑定（第 3 步）

当前交付面向本机轻单。网页入口 `http://127.0.0.1:8790`，Worker 为 `http://127.0.0.1:8788`。用当前 Windows 账号运行 `npm run dev:agent`，然后打开「Agent 验证 → 3 · 绑定电脑」。

## 保存与连接

- `.tmp/runner-device/device.sqlite` 保存设备身份、允许目录、命令回执、未确认事件及租约状态；不要在运行期间删除。
- Windows Credential Manager 保存当前设备密钥，目标限定在 `QingdanRunner/v1/` 命名空间。系统调用只读取指定目标；没有凭据枚举。密钥经匿名 stdin 传给辅助程序，参数、日志和 JSON 配置没有密钥。
- 账号创建 10 分钟有效的一次性配对码；Runner 使用已保存身份提交密钥摘要。配对响应丢失时保留原身份，重试核对原设备，避免重复登记。
- Runner 用设备密钥换取 15 分钟连接令牌，主动建立带 Bearer 的原生 WebSocket。每 15 秒心跳，45 秒未确认则离线；异常时退避重连，令牌到期前换新。浏览器关闭不会终止 Runner。
- 本机启动器重新启动后恢复同一设备和目录。如果配对曾在保存身份后中断，服务仍不可达时会保持待核对状态；恢复服务后再次点击绑定可使用原身份核对。
- 撤销设备会增加授权版本、使旧令牌和清单关联失效并关闭连接。撤销后才清理本机凭据；普通网络错误不会删除绑定。

## 项目与并发

授权范围是用户明确选择的真实目录。目录身份、Windows 大小写、路径分隔符以及 junction 跳转都会被检查；子路径不能穿出授权根，注册路径被替换时拒绝使用。Git 工作树根只用于锁的归一化，不会扩大目录授权。

跨进程的项目锁位于当前用户的 `QingdanRunner/locks` 目录，相同 Git 工作树在不同 Runner 状态目录仍使用同一把锁。60 秒执行租约失效后保留占用，必须确认原运行已停止才能释放，不自动接管。第 4 步的执行消费者需先取得该锁；本步骤不运行收到的执行命令。

连接版本防止旧连接继续提交或续租。命令与事件的相同编号只允许相同内容；接收方先持久化再回执。未确认事件会补发，已确认的事件不重发。项目关联使用当前账号、画布所有权及绑定版本核对。

## 验证与排查

```powershell
npm run test:devices
npm run runner:build
node scripts/runner-vault-smoke.mjs
```

凭据检查只创建一个临时 Runner 目标，核对写入/读取/删除，最后清理它；不会读取其他程序凭据。该命令须用运行 Runner 的 Windows 账号执行。

界面显示「本机 Runner 尚未启动」时，请从上述启动器进入 8790。普通 `npm run dev` 不启用设备连接。检查同一电脑上的 8788/8790 是否被另一份启动器占用；启动器必须在已配对的 Windows 用户下运行。

断线时先观察错误与最近心跳，再尝试「重新连接」。授权目录不存在或被替换时，恢复原目录或显式移除后重新登记；不要修改 SQLite 绕过检查。运行占用未确认停止时，保持锁和租约，等待后续执行核对入口。

生产与 preview 的 `RUNNER_ENABLED` 默认关闭。此交付未应用生产迁移、未发布线上服务；生产发布仍遵循项目已有的手工部署流程。
