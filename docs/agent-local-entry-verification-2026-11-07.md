# 普通网页接入本机 Agent 的修复验证

## 故障与原因

用户在“选择 Codex 会话”面板看到“接口不存在”。普通网页位于 `127.0.0.1:8788`，此前本机请求使用相对地址，被送入不提供 `/api/local-runner/*` 的 Worker。运行日志也出现该路径的 404。旧 `npm run dev` 只启动网页；当时 `agent:diagnose` 显示 Agent 服务未运行，8790 不可用。

上一轮会话入口验证覆盖了 Agent 入口和组件，但遗漏了普通网页跨端口访问。此次补充这一实际入口的回归。

后续实际登录态检查又确认设备仍绑定旧测试账号；该问题及浏览器端恢复结果见 [电脑账号冲突恢复验证](agent-account-conflict-verification-2026-11-07.md)。服务就绪不能替代当前用户的配对验证。

## 修复

- 普通网页 8788 和 Vite 页面 5178 自动调用 8790 本机服务，携带当前登录 Cookie 和账号标记；8790 页面继续同源调用。
- 只有上述本地来源能够跨端口访问本机 Runner API。保留 Host、来源、请求标记、登录和账号归属检查；其他本机诊断、代理与 WebSocket 的访问范围不扩大。
- `npm run dev` 与 `npm run dev:agent` 均启动完整网页与 Agent 服务；原有双击启动脚本仍可使用。项目 Node 要求统一为 24+。
- Vite 代理只将确切的本地开发来源转换为 Worker 来源，允许正常 API 与 WebSocket 请求。
- 选会话后自动关联项目，每次提交新建会话的规则保持不变。

## 真实本机验证

确认活动任务数为 0、无未知执行状态后，按监听端口、可执行文件路径和父进程链核实并停止本项目旧网页启动器，使用已安装的 Agent 启动完整服务。未清理数据或重置凭据。

- `agent:diagnose`：`status=running`、`ready=true`，8788/8790 均在监听。
- 真实 8790 服务对 8788、5178 来源预检均返回 204，允许携带凭据。
- 无登录 Cookie 的真实会话请求返回 401，证明已到达存在的受保护接口，未绕过登录；不再是缺失路由 404。
- 真实 `/api/local-codex/connection`：`authenticated=true`，Codex 版本 `0.167.0-alpha.3.2`。
- 真实 Codex 只读读取 50 条会话及下一页游标，并再次读取首条元数据核实；执行轮次为 0。
- 脱敏运行结果：`.tmp/agent-local-entry-runtime-2026-11-07.json`。

没有读取浏览器登录凭据，也没有进行实际浏览器登录后的端到端操作。真实服务探测、协议读取与带登录态的隔离 HTTP 回归分别验证对应边界。已打开的旧页面需要刷新以载入新客户端代码。
