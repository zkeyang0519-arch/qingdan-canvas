# 在轻单里逐步体验 Agent

> 2026-11-13：仅「Agent 验证」按钮、八步验证弹窗和专用试验页面已移除。正式 Agent 模块、项目聊天、待办执行、记忆、项目摘要及诊断恢复继续保留。下文第 1–8 步的验证页面入口属于历史记录；正式 Agent 的操作说明仍适用。

从第 1 步开始，每一步都必须提供轻单内的操作入口、真实结果和体验步骤。第 9 步负责整合、完善界面，不再等到第 9 步才展示此前功能。

## 打开入口

使用已登录 Codex 的 Windows 账号，在项目目录运行：

```powershell
cd D:\TODO\qingdan-canvas
npm ci
npm run dev:agent
```

需要 Node.js 24 和 Codex CLI 0.167.0-alpha.4.1。打开 <http://127.0.0.1:8790>，登录本地轻单账号，进入画布，点击与「画布 / 排列」并列的 **Agent**，进入正式工作区。旧的 **Agent 验证** 入口已移除。

正式 Agent 打开即显示 **选择项目**，列表只展示项目名称和目录，同一目录自动合并。可以按名称或路径筛选已加载项目，或加载更多项目；选中后自动连接当前电脑，并关联到界面标明的轻单项目。没有轻单项目时自动用目录名创建一个，已有同目录绑定直接复用。每次提交待办会在所选目录新建一个执行会话，无需选择历史对话。右上角可重新选择项目；电脑设置保留为诊断和手动调整入口。直接查看已有运行时优先显示运行进度。

「待办与执行」在未完成列表底部提供「＋ 添加待办」。点击后只展开与排列模式相似的一行正文输入，按 Enter 或点击勾号保存，Shift + Enter 换行，Esc 或叉号收起并保留草稿。新增和编辑都只显示待办正文；编辑已有任务时保留原执行要求及验收条件。保存后仍可连续输入，正常保存过程不会在列表上方插入恢复面板；只有结果不确定时才显示待核对操作。无论是否关联 Codex 项目，新建待办均写入同一份共享画布，在 Agent、画布和排列视图中显示。新条目的执行规格尚未同步时会显示「正在同步」，同步完成后才可选择执行。保存待办不会启动 Codex；未保存输入按账号、画布和项目保留。

项目聊天输入框用于轻单助手对话。「待办与执行」顶部的「执行设置」统一管理提交待办时的新会话默认模型与快速模式；模型目录从绑定电脑的 Codex 完整读取，可在页面内搜索和刷新。保存的模型与快速模式随新执行固化，重试沿用原设置；不支持快速模式的模型不能开启此选项。设置按账号、画布及项目绑定保留，执行使用右侧当前选择的权限。「绑定 agent」统一管理执行设备和 Codex 项目，首次先选择设备，再选择项目；已有绑定在刷新后恢复。

模型正文下方的复制、引用按钮只显示图标，悬停或读屏可查看名称。执行状态旁的用时每秒更新，结束后显示固定用时；已有记录缺少可靠时间戳时不显示估算值。待办列表采用紧凑行距，省略无附加要求时的解释文字。

主列表显示共享画布中尚未完成且未收起的待办，顶部提供「全选待办 / 取消全选」。全选跳过锁定、正在同步、需要重新确认要求、已完成和执行结束待核对的任务；超过每批 50 项时，明确提示仅选择清单顺序的前 50 项。勾选仅用于选择要交给 Agent 执行的待办；右侧「标记完成」独立修改待办状态。全选本身不会提交执行。

列表下方有默认折叠的「已完成」收集框，仅收集共享画布中已完成的待办。点击「标记完成」或「移回待办」会同步修改画布和排列视图中的状态；在画布或排列中修改状态，也会反映到 Agent。整组 Agent 执行正常结束并确认停止后，同版本且尚未完成的来源待办自动收进独立的「已执行，待核对」折叠区，由用户核对后标记完成，或移回主列表继续处理。折叠不改变待办完成状态；内容发生变化或尚未同步的条目保留在主列表。当前浏览器按账号与项目绑定记住已看到的来源运行及继续处理选择；清除浏览器数据或换浏览器后只能从服务端近期记录恢复。

右上角和项目导航的数量统计非空的真实待办，不包含空白编辑行、未保存输入或正文便签；待核对的执行项仍计入未完成数，并单列待核对数量。接口只返回部分执行信息时，仍显示完整画布中的待办，并提示部分执行信息尚未同步。

每条待办右侧提供删除按钮，未完成和已完成的待办均可删除，锁定内容需先解锁。删除会同步到画布并连同备注移入回收站，可通过提示中的「撤销」或回收站恢复；删除待办不会停止已提交的执行批次。

本地与线上账号数据库独立。已有本地账号可直接登录；新注册的邮件配置遵循 README。本次浏览器验收使用专门创建的本地测试账号，不涉及线上账号或生产数据。

`npm run dev` 和 `npm run dev:agent` 均自动构建网页和 Runner，迁移本地 D1，并通过 8790 转发 8788 的轻单 HTTP / WebSocket。普通本机网页（127.0.0.1:8788）与 Vite 开发页（127.0.0.1:5178）会自动将本机 Runner 请求发到 8790，并保留当前登录状态。请先关闭另一个占用 8788/8790 的开发服务。重新启动保留清单和验证记录。修改前端后需重新构建并刷新页面；修改本机服务后重新启动。

## 第 1 步：任务规则

1. 进入「1 · 任务规则」，点击「载入示例」。可以修改做什么、执行要求、完成条件、优先级和截止时间。
2. 点击「校验并排序」：即使 B 的优先级更高，只要 B 依赖 A，仍显示 A → B。
3. 勾选 A 依赖 B，再校验：显示两项互相等待的具体路径。取消这条依赖后可恢复正常。
4. 用上移/下移调整草稿，点击「校验当前顺序」：依赖被颠倒时指出哪项必须先做。
5. 选择清单项目并点击「从清单复制未完成项」。只复制当前正文，执行要求和完成条件由你补全。

草稿按账号和画布自动保存在当前浏览器。复制或载入示例会替换面板中的验证草稿。此阶段预览规则和顺序；正式清单的执行规格与排序写回将在第 5 步接入。

## 第 2 步：本机 Codex

1. 进入「2 · 本机 Codex」，点击「检查连接」，查看真实登录状态、固定版本和本机注册的项目。
2. 展开「查看项目会话」，点击一条会话读取要求和 Codex 输出。当前入口登记轻单源码项目和最近的验证项目，每个项目展示最近 100 条会话。
3. 点击「运行三会话测试」。使用当前 Codex 账号额度，在 `.tmp/agent-experience/projects/<请求编号>` 创建独立项目，依次新建总结、A、B 会话。
4. 面板显示阶段、输出、会话编号和文件验证结果。成功时显示「3 个独立会话验证通过」。测试完再次检查连接，可选择验证项目读取三个会话。
5. 刷新页面、关闭并重开面板，仍可读取原测试状态；请求重试复用同一个编号。

状态保存在 `.tmp/agent-experience/sessions.json`，快照、SQLite 与报告在各验证项目旁的 `.runner` 目录。不要在运行期间删除这些文件。

服务中断显示「需要核对上次测试」。「核对上次测试」使用原目录、runId 和会话核对，不会把未知结果当作新任务重发。确认所有运行已终止的失败显示「测试未通过」，允许修正原因后新建测试。遇到 Codex 审批、登录或仍无法确认的运行会显示错误，当前面板不自动批准。

该入口仅绑定 127.0.0.1，校验 Host、Origin 和同源请求头。三会话测试使用程序创建的隔离目录；第 3 步允许通过独立入口明确授权项目目录。本次没有部署生产网页。

## 第 3 步：绑定这台电脑

继续使用 `npm run dev:agent` 启动的本机入口，进入 **Agent 验证 → 3 · 绑定电脑**：

1. 填写电脑名称，点击「绑定这台电脑」。使用当前轻单账号完成一次性配对；成功后显示电脑状态、轻单识别状态和最近心跳。
2. 在「允许执行的项目」点击「从 Codex 获取」，从本机 Codex 会话读取项目目录。同一目录会合并显示，较早的项目可通过「加载更多项目」继续读取；点击项目旁的「添加」后才会授权，已添加的项目会标注状态。没有会话的目录可展开「手动填写目录」添加。删除项目会停用对应清单关联。
3. 选择当前画布的清单与执行项目，点击「绑定到当前清单」。成功后显示绑定的项目名称；已有绑定发生变化时会要求刷新，避免覆盖其他操作。
4. 点击「暂时断开」，观察离线；点击「继续连接」恢复。也可点击「重新连接」检查连接恢复。
5. 关闭网页后，本机服务继续保持连接。重开入口仍显示原设备和项目；停止并重新运行 `npm run dev:agent` 后会从保存的配置与系统凭据恢复连接。
6. 「解除绑定 → 确认解除绑定」先撤销服务端授权，再删除本机设备凭据和目录登记。之后可以重新配对。存在尚未确认停止的运行时，不允许清理本机运行状态。

本机入口通过当前登录会话校验账号；切换到其他账号不能控制这台已绑定设备。设备密钥仅保存在当前 Windows 用户的凭据管理器，普通配置、日志、网页都不保存它。配对与连接必须使用同一个 Windows 用户启动服务。

本步骤完成设备连接和项目关联，第 4 步在这条连接上派单。启动器需要持续运行；Windows 开机自启与安装包完善属于第 10 步。本机账号和绑定与线上环境独立。更多连接机制与排查见 [Runner 设备绑定](agent-device-binding.md)。

## 第 4 步：MCP 派单

进入 **Agent 验证 → 4 · MCP 派单**，先填写 **新建项目名称**，点击 **创建项目**，再填写执行要求和完成标准并点击 **提交任务**。文件夹和显示名使用你输入的名称，同名项目保留原结果；不同命名项目分别保存派单记录。默认示例会创建 `hello.txt`。发给 Codex 的内容是自然语言任务及必要背景，新会话标题不附加运行编号。

完成后输入补充说明，可以在原会话继续一轮；执行过程中可以请求停止，界面等待本机确认后再显示停止结果。旧测试目录没有被移动，仍可选择 **独立测试项目** 查看以前的记录。

也可选择已关联的清单项目，输入执行要求和完成标准，或只总结项目。详细体验步骤、接口与范围见 [MCP 派单](agent-execution-mcp.md)。

## 第 6 步：聊天与记忆

在项目目录的 `.dev.vars` 中填写本机聊天模型配置。`ROUTER_API_KEY` 使用你自己的 DeepSeek API 密钥，`ROUTER_BASE_URL` 使用 `https://api.deepseek.com`，`ROUTER_API_FORMAT` 设为 `chat_completions`，`ROUTER_MODEL` 设为 `deepseek-flash`。修改后重新运行 `npm run dev:agent`。模型未配置时，页面会提示完成服务端配置，记忆管理仍可使用。

1. 打开 **Agent 验证 → 6 · 聊天与记忆**，从「项目清单」选择真实清单。需要先在第 3 步为该清单关联电脑和执行项目。
2. 启用第7步后，页面会读取已选项目的摘要；尚无摘要时点击「开始总结」，摘要就绪后再点击「发送」。可以先输入草稿等待总结。可点击「新聊天」另开聊天并重新总结当前项目，也可从「聊天历史」回到已有对话；普通刷新不会重开总结。
3. 回复含有待办提案时，可以编辑待办内容、执行要求和完成标准，再点击「保存到真实清单」。这一步只写入清单。点击「打开第 5 步」可在同一清单查看、排序待办，由你选中待办并提交批次后才开始执行。
4. 在「管理记忆」中切换「个人记忆」与「当前项目记忆」，可查看、新增、编辑和删除。回复中的记忆建议需点击「记住」才会保存，列表会标明来源。删除记忆后，模型后续会跳过已删除的来源，聊天原文与已保存的待办仍可查看。

个人记忆可用于同一账号的各个项目。项目记忆跟随当前轻单清单或分组，更换该分组关联的执行目录后仍可继续使用原有聊天和记忆。

## 第 7 步：项目总结

打开 **Agent 验证 → 7 · 项目总结**，从「请选择要总结的项目」选择已在第3步关联电脑和目录的清单。首次选择会在该目录新建一次只读的 Codex 总结，已有任务占用执行端时先等待；重新打开页面并选择同一项目会读取同一次总结的进度。

新报告是供其他开发者接手的完整项目交接报告，按六部分展示：项目目标与当前状态、已完成与未完成、最近完成的工作、当前停在哪里、修改入口、接手顺序与验证。技术结构和运行范围说明项目如何工作；模块区分已实现、已验证、未完成及待核实；近期改动包含已核对的工作区修改；具体入口列出实际读过的相对文件路径、职责及何时需要修改；下一步按优先级给出工作、依赖和可观察的验收标准。仅建议或尚待用户确认的需求不会写成已确定任务，历史测试结果不会冒充本轮执行。

报告不限 350 字，按项目复杂度保留足以接手的细节。摘要页和聊天使用相同的完整六部分正文，不截成简报；读取范围与来源可展开查看。报告标明生成时间与版本，自动作为一条助手消息保存到该轻单项目的聊天中；同一版本不会因刷新重复发送，没有聊天时自动创建项目聊天，原有消息和草稿保留。轻单 Agent 后续聊天与执行也会收到修改入口、接手约束和验收方法。旧版摘要继续使用原有布局，在途旧总结仍可交付原格式。

「刷新总结状态」只核对进度；「重新总结」创建一次新的只读总结。新摘要使用 GPT-6.1 Terra、medium 推理强度，普通开发任务保留原模型；已开始的旧摘要续跑保留原模式和设置。新摘要显示已查看文件数、最近记录数、用时和模型，不设全部历史的读取百分比。

Codex 从当前绑定目录出发，按需浏览一层目录、读取关键文件、查看 Git 变更，结合项目说明与实现判断现状。需要目标背景时才查询最近相关会话，选取需要的记录；没有历史也可直接检查项目。信息足够即可提交报告，不要求遍历全部文件、读取全部历史或提交末页回执。已读取范围内的结论保留来源，未核实内容简短标明；历史中的完成声明不等于本轮验收。

摘要页的「Codex 读取与输出」持续增量展示真实读取动作与助手公开文字，并自动跟随最新输出；上滑查看已有内容时不强制拉回底部。输出沿用带权限校验的运行事件接口，每秒补读新增事件；断线后保留已有内容并自动恢复，切换项目或重新总结时隔离运行。显示窗口保留最近 60000 字符，截断时明确提示。完成后的完整报告直接显示在摘要页并自动写入聊天。

等待或运行中的总结可以点击「停止总结」。页面会持续核对本机状态，收到实际结束确认后才允许重新总结；停止请求的回执丢失时可重试同一次请求。总结失败时显示原因；有上次摘要时需明确点击「使用上次摘要」才用于聊天。更换执行项目后必须重新总结。

本机使用 `npm run dev:agent` 即启用第7步。只读检查不修改文件、不执行待办，历史查询不会恢复或续写来源会话；其他项目、子 agent、来源不明分叉、临时会话和轻单项目总结被排除。旧版的全量历史分页、缓存与末页校验仅用于恢复已有运行；新发起的摘要采用按需读取。此前版本验收见 [第七步验收](agent-project-summary-verification-2026-11-05.md)。

电脑报告总结完成后，摘要正文可能稍后回传。这时页面显示「正在接收摘要」并持续读取状态，当前轮次正文到达后自动展示到聊天；关闭摘要抽屉也会继续接收。不会因短暂缺少正文而提示总结失败或重复启动。已有摘要在此期间保留为上次结果。如需退出等待，可点「停止等待」；迟到结果不会重新启用已取消的总结。

## 第 8 步：批次执行与验收

在 **5 · 真实清单** 或 Agent 的「待办与执行」中，保存待办后勾选要执行的项目，再点击「提交所选待办」。执行要求和完成标准可选：未填写执行要求时使用待办内容，未设置验收条件时默认由你人工确认。提交时先按待办版本保存缺失的要求，保存结果不确定时停止派单并保留原请求供核对；仅保存或勾选待办不会执行。已有要求与验收条件会保留；锁定、完成或内容变更后尚未重新确认的待办不能提交，按钮旁会说明当前原因。

每项的「验收方式」默认为**人工确认**：Codex 执行结束后，需要你核对结果并确认，才会继续下一项。可明确选择**文件检查**，填写项目内的相对路径，再选择检查文件存在或包含指定文字；系统会根据实际文件检查结果验收，不会把自然语言中的“已完成”直接当作通过。

选中待办并点击「提交所选待办」后，自动进入 **8 · 批次执行**，查看刚提交的同一个批次。一次提交的全部待办共用一个 Codex 会话、按清单顺序逐项执行；下一次提交另建会话。也可以从第5步派单记录点击「查看批次」，或在第8步切换项目及历史批次；查看、刷新页面不会重新提交待办。

- **当前项完成后暂停**：当前项继续执行、验收并更新清单，后续待办暂不开始。页面确认「已暂停」后，点击「继续批次」恢复剩余待办。
- **确认本项验收通过**：仅在等待人工验收时出现。先核对本项完成标准与执行输出，再确认；系统仍需收到清单更新结果，才会继续。
- **立即停止**：点击后再确认停止本批次；页面持续等待本机实际停止确认。已完成的结果保留，后续未执行的待办不会被勾选。
- **处理异常**：页面显示具体原因和验收记录。当前执行已结束且可继续时，可以「补充说明并继续当前项」，内容发送到原会话；「重新核对结果」只重查执行结果或清单写回，不另建批次。执行中收到的原生审批或工具提问会显示专用弹窗，普通补充说明不会代替这些请求。

「正在更新清单」表示当前项已执行但清单状态尚未确认更新；出现待办变化、清单更新失败等提示时，需核对后处理。若提交时关闭「自动勾选完成」，验收后会保留原清单勾选状态。旧版本产生的批次可以查看既有记录，逐项控制只适用于启用本步骤后创建的批次。

文件验收明确失败时最多自动修复一次，并在原会话重新检查。再次失败或验收条件暂不支持时，需要停止原批次、调整要求或文件，再重新提交未完成项；「重新核对结果」不会重新读取手工修改后的文件或增加修复次数。本页提供文件存在/包含文字检查，测试命令执行尚未接入。

### 执行权限与人工询问

第 5 步提交区域的「权限」按钮提供完全访问、只读、项目内编辑（按需人工批准）、项目内编辑（自动安全审查）四档。新执行任务默认**完全访问**：可读写本机文件、访问网络，Codex 执行操作无需逐次审批。其余档位默认关闭网络，保留人工批准或自动安全审查方式。项目摘要始终只读。

升级后使用新的权限偏好版本，新提交任务默认完全访问；之后明确选择的档位记在本浏览器当前账号和项目关联下，只影响下一次提交。项目关联变更后回到默认选择。第 8 步显示每个批次提交时记录的权限，旧记录没有权限字段时明确显示「旧批次：权限未记录」。已提交批次及恢复执行继续使用原权限，不自动重试之前拒绝的请求。

受限档位的原生审批弹窗展示请求原因、命令、执行目录或文件路径，以本机提供的信息为准。「仅本次同意」「拒绝本次操作」「取消当前请求」只对当前请求生效，不改变后续操作的默认权限。命令审批可能允许该次操作超出项目目录或默认网络限制，弹窗会明确说明后由用户决定。只读、会话级权限或其他不能完整展示范围的请求禁用同意。所有档位的原生工具提问仍按原问题逐项回答，固定选项的问题仅提供对应选项，允许补充的问题显示输入框。完全访问不代替你回答业务问题，人工模式下轻单不会自动选择、提交回答或批准。

发送结果不确定时，可以重试同一次选择，避免重复请求；成功提交后仍等待本机确认。请求过期、执行结束或停止后不再提供可操作弹窗。「稍后处理」只收起弹窗，不会批准或拒绝。

轻单会关注本页最近提交或查看的批次。切换 Agent 标签页或关闭 Agent 验证后，仍可在当前画布收到待处理请求提醒；点击「查看并处理请求」回到准确的批次。该目标按账号和画布保存在当前浏览器会话中，刷新后可恢复，不扫描其他项目的运行。

## 第 9 步：正式 Agent 工作区

1. 顶部选择 **Agent**；左侧切换项目。桌面同时显示项目聊天和「待办与执行」；手机通过顶部项目选择及「项目聊天 / 待办与执行」切换。
2. 点击右上角「电脑与项目设置」查看连接和当前执行目录。「项目摘要」按需打开，打开页面或抽屉不会自行新建总结任务。
3. 在聊天中整理要求，确认提案后点击「保存到真实清单」。相邻清单自动刷新；编辑入口只修改正文，用上移/下移调整顺序。已有执行要求和验收条件继续保留。
4. 选中待办，点击「权限」检查本批次权限，再「提交所选待办」。一次提交在一个 Codex 会话依次执行；下一次提交新建会话。进度区保留暂停、继续、停止、验收与异常处理，原生审批/提问会弹出；其他已查看项目有待处理请求时也保留提醒。
5. 右上角「记忆」可查看、新增、编辑和删除个人/项目记忆。打开抽屉或切换项目不会丢掉当前标签页未发送的聊天与待办草稿；草稿按账号、画布、项目、关联版本及聊天隔离。

草稿和待核对请求 ID 存在当前浏览器标签页，不承诺跨设备草稿同步。聊天使用实际模型异步回复，并显示等待、失败状态，不伪造逐字流式效果。执行与清单状态以服务端记录为准，刷新不重新执行。正式排序沿用真实清单的上移/下移；画布及排列原有拖动行为保留。

本轮实际验收：三项提案保存与排序、记忆新增/修改/删除、项目切换草稿恢复、390px 窄屏、当前目录和权限设置；重读第八步已完成三待办的结果。未新派发这三项界面测试待办，也未扩大执行权限。详见 [第九步验收记录](agent-workspace-verification-2026-11-05.md)。
