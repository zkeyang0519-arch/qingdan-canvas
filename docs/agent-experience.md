# 在轻单里逐步体验 Agent

从第 1 步开始，每一步都必须提供轻单内的操作入口、真实结果和体验步骤。第 9 步负责整合、完善界面，不再等到第 9 步才展示此前功能。

## 打开入口

使用已登录 Codex 的 Windows 账号，在项目目录运行：

```powershell
cd D:\TODO\qingdan-canvas
npm ci
npm run dev:agent
```

需要 Node.js 24 和 Codex CLI 0.166.0-alpha.5.1。打开 <http://127.0.0.1:8790>，登录本地轻单账号，进入画布，点击顶部 **Agent 验证**。画布与排列模式都提供该按钮。

本地与线上账号数据库独立。已有本地账号可直接登录；新注册的邮件配置遵循 README。本次浏览器验收使用专门创建的本地测试账号，不涉及线上账号或生产数据。

`dev:agent` 自动构建网页和 Runner，迁移本地 D1，并通过 8790 转发 8788 的轻单 HTTP / WebSocket。请先关闭另一个占用 8788/8790 的开发服务。重新启动保留清单和验证记录。修改前端后需重新构建并刷新页面；修改本机服务后重新启动。

## 第 1 步：任务规则

1. 进入「1 · 任务规则」，点击「载入示例」。可以修改做什么、执行要求、完成条件、优先级和截止时间。
2. 点击「校验并排序」：即使 B 的优先级更高，只要 B 依赖 A，仍显示 A → B。
3. 勾选 A 依赖 B，再校验：显示两项互相等待的具体路径。取消这条依赖后可恢复正常。
4. 用上移/下移调整草稿，点击「校验当前顺序」：依赖被颠倒时指出哪项必须先做。
5. 选择清单项目并点击「从清单复制未完成项」。只复制当前正文，执行要求和完成条件由你补全。

草稿按账号和画布自动保存在当前浏览器。复制或载入示例会替换面板中的验证草稿。此阶段预览规则和顺序；正式清单的执行规格与排序写回将在第 5 步接入。

## 第 2 步：本机 Codex

1. 进入「2 · 本机 Codex」，点击「检查连接」，查看真实登录状态、固定版本和本机注册的项目。
2. 展开「查看项目会话」，点击一条会话读取要求和 Codex 输出。当前入口登记轻单源码项目和最近的验证项目，每个项目展示最近 100 条会话。
3. 点击「运行三会话测试」。使用当前 Codex 账号额度，在 `.tmp/agent-experience/projects/<请求编号>` 创建独立项目，依次新建总结、A、B 会话。
4. 面板显示阶段、输出、会话编号和文件验证结果。成功时显示「3 个独立会话验证通过」。测试完再次检查连接，可选择验证项目读取三个会话。
5. 刷新页面、关闭并重开面板，仍可读取原测试状态；请求重试复用同一个编号。

状态保存在 `.tmp/agent-experience/sessions.json`，快照、SQLite 与报告在各验证项目旁的 `.runner` 目录。不要在运行期间删除这些文件。

服务中断显示「需要核对上次测试」。「核对上次测试」使用原目录、runId 和会话核对，不会把未知结果当作新任务重发。确认所有运行已终止的失败显示「测试未通过」，允许修正原因后新建测试。遇到 Codex 审批、登录或仍无法确认的运行会显示错误，当前面板不自动批准。

该入口仅绑定 127.0.0.1，校验 Host、Origin 和同源请求头；不允许网页提交任意命令或工作目录。设备配对与云端调度将在第 3/4 步实现；本次没有部署生产网页。

## 后续每一步的界面验收

| 步骤 | 体验入口 | 可观察的验证结果 |
| --- | --- | --- |
| 1 | 任务规则、依赖与排序验证 | 缺失信息、循环依赖、合法顺序 |
| 2 | 本机连接、项目/会话、三会话测试 | 真实会话编号、输出和文件核对 |
| 3 | 设备配对、允许的项目、在线状态 | 上线、断线及重连状态 |
| 4 | 提交任务、进度、补充说明、停止 | 派单回执与本机执行状态 |
| 5 | 生成待办、编辑执行要求、排序 | 正式清单写入并同步到其他页面 |
| 6 | 聊天、记忆查看/修改/删除 | 对话记录和保存的偏好、决策 |
| 7 | 选项目、重新总结、查看摘要 | 独立总结会话和当前项目进度 |
| 8 | 开始、暂停、继续、处理异常 | 逐项推进、验收和更新清单 |
| 9 | 完整项目工作区 | 连贯的选项目到查看结果流程 |
| 10 | 连接诊断、恢复记录与核对入口 | 断网/重启后恢复、无重复派发 |

## 开发验证

```powershell
npm run test:experience
npm test
npm run check
npm run runner:check
npm run deploy:check
```

行为测试覆盖规则错误、清单复制、草稿隔离、连接失败、结果显示、请求幂等、恢复、已终止失败、启动中退出、跨站和异常 Host/路径。自动化测试使用模拟输入；真实 Codex 通过上述界面操作验收。
